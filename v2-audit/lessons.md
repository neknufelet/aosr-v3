## 反覆出現的根因模式（批評者歸納）

- 規則文字、守衛掃描範圍、實際程式三者各自漂移，而守衛豁免的正是規則禁止的形狀（CLAUDE.md 禁 JAX_PLATFORM_NAME setdefault ↔ conftest.py:14 就是它 ↔ hash guard 不掃 tests/、整檔豁免 21 支 probe；SSOT 表禁 lib/ 重定義軸 ↔ scoring_v2_stage1 手抄一份 ↔ 硬規則只點名 scripts/）。
- 「加段不改上文」讓同一份檔在 HEAD 自相矛盾且守衛 PASS：next.md 併回/未併回、GUARD.md 未成單/已 CLOSED、CLAUDE.md 守衛節橫幅說停用而下文仍教你跑——doc-topology 與 check_claude_md 只驗形狀不驗真偽。
- 決定性狀態活在本機或對話記憶而非版控：凍結靠 hooksPath／mask／uninstall 三道本機開關、git identity 是 fixture 殘留、v3 決策只在 memory 與橫幅、cairn 零紀錄——換一台機器或一個 session 就全部消失。
- 「來源」用字串或註解宣告而不用 import／hash 綁定：`frequency_axis_source_path` 只是字串、84.49 Hz 旁註「This f0 will drift if the construction changes」沒有任何測試守、freq_axis 文件裡的 fixture 說明靠人記——宣稱與被宣稱物之間沒有機器連結，漂了沒人知道。
- 守衛出貨時沒先證明它會咬：addopts `--strict-markers` 啞了整張工單、probe_* 豁免 glob 沒 rot 測試、hash guard 深度截斷 131 條鏈仍 PASS、check_guards 自身失敗路徑一律靜默 exit 0——只會回綠的檢查與沒有檢查在畫面上同貌。
- 每 session 載入檔是所有教訓的預設落點：CLAUDE.md 九月 31 個 commit（09-05 單日 15 個）、432 行、`等級:` 申報 8 處對上百條規則；核心九條自己（Any 360／print 88）都沒有執行者，inline 規則的存在感遠大於它的執行力。

## 批評者認為分類錯的

- red-test-debt-grew-unwatched → 應為 rule（直到 repo 公開或升 GitHub Pro 才能升格 structure）：其 structure 依據是「CI 是唯一執行者、每 PR 必跑、main 永遠綠」，前提是 required status checks 擋 merge；commits-never-pushed-single-disk／amended-a-pushed-commit 已記 `/branches/main/protection` 回 403，本次對 aosr-v2 重現：`gh api repos/neknufelet/aosr-v2/branches/main/protection` → 403「Upgrade to GitHub Pro or make this repository public」，`.private=true`。沒有 required checks 的 CI 只是「會印警告」，紅了照樣能併——這正是 red-test-debt-grew-unwatched 自己描述的病（fork CI 三次全紅無人看，acceptance-criteria-impossible-when-written）。
- enforcer-declared-but-never-installed → 應為 rule：v3 對策「每個 check 都是 on-push job 並列為 branch protection 的 required status check——沒跑的 check 直接擋 merge」在 private 免費方案不可用（同上 403 實測）；缺了「擋 merge」這一環，registry＋regenerate-diff 只是會印紅字的 CI，等級是「會印警告」，仍需人看，回到 enforcer-declared-but-never-installed 自己反對的「人的審查當執行者」。
- guard-of-guards-silently-dies → 應為 rule：「執行者權威改掛 CI＋required status checks，本機 pre-commit 只是可選鏡像」——required checks 在此 repo 方案下為 403；沒有它，「守衛的守衛」問題並未結構性消失，只是從本機 hook 搬到沒人被迫看的 CI 頁面。
- acceptance-criteria-impossible-when-written → 應為 rule（bucket 不變），但 enforcer 欄應改為「沒有人」或改掛本機 pre-push：enforcer 寫「GitHub branch protection required check」，與 commits-never-pushed-single-disk 同一份 403 證據衝突；清單內部自相矛盾（commits-never-pushed-single-disk 明寫「伺服器端擋不住，這條只能是 rule 不是 structure」，acceptance-criteria-impossible-when-written 卻引用它當執行者）。
- blind-staging-mixes-unreviewed-work → 應為 rule（bucket 不變），enforcer 欄應改為本機 hook＋CI path-filter「會印警告」：enforcer「branch protection（禁直推 main、PR 必過 CI）」在本 repo 為 403 不可設；只剩 `.githooks/pre-push`（掛載點 2，可 `--no-verify` 繞）與 CI 警告。
- two-jax-suites-freeze-the-machine → 應為 structure：其 enforcer 欄自述「tests/conftest.py 的 session lock……第二個 session 阻塞等待＝會擋下」——互斥鎖讓「兩個 JAX pytest 同時跑」這個壞狀態在構造上不可能發生（tests/conftest.py:44-56，ebf188a9 實測「持鎖時第二個 pytest 阻塞」），這是結構不是檢查；bucket 卻標 rule。若嫌鎖有 global-lock-reentrancy-deadlocks-itself 的重入盲點，那是 structure 的缺陷，不是它變成 rule 的理由。
