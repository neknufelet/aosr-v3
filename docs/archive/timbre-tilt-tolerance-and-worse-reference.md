# 音色傾斜的容許帶 1.0 與較差參考 2.0（這一條同時升成正式數字）

本紙接在 `timbre-target-tilt-is-flat-from-standards.md`（票 #368，目標值 0）後面，不取代它：那一張定的是目標值，這一張定同一條剩下的兩個數字，並把整條的狀態從測試基線升成正式數字。

## 問題

目標傾斜已經拍成 0（平坦）。同一條還剩兩個佔位數字：容許帶 0.5 dB／八度與較差參考 2.0 dB／八度。代價的算式是 `max(0, |量到的傾斜| − 容許帶) ÷ 較差參考`，所以「容許帶」是零代價的寬度、「容許帶＋較差參考」是代價到 1 的位置。這兩格不拍，這一條就停在測試基線，已經拍好的目標值也跟著升不上正式數字。

查證表（票 #358）的結論是：**標準沒有給傾斜的容許帶**，它給的是頻響的 ±3 dB 容許帶。要用標準當依據只能換算，而換算結果取決於拿哪一段換。較差參考則完全沒有原文可引。

## 選項

- **A**：容許帶 1.0 dB／八度、較差參考 2.0 dB／八度。容許帶是把 ±3 dB 換算到傾斜擬合段 80–4000 Hz（5.64 個八度，純傾斜線在兩端各偏半個跨距，上限 1.06）取的整數；較差參考標產品選擇。
- **B**：容許帶維持 0.5、較差參考 2.0。更嚴，但 0.5 沒有任何來源，是純產品選擇。

另一種比 A 寬的讀法：只拿標準畫 ±3 dB 那一段（250 Hz–2 kHz，3 個八度）換算，上限是 2.0 dB／八度。標準在那一段以外本來就放寬下限，所以這個讀法站得住，只是寬得多。

## 決定

採 A。容許帶 1.0、較差參考 2.0，兩個數字寫進 `src/aosr/config/data/quality_targets.toml` 的 `timbre_balance.target_tilt_db_per_octave`。

三個數字都拍完了，所以這一條的狀態從測試基線升成**正式數字**。出處種類那一格照票 #376 的附帶說明處理：**整條標產品選擇**，出處字串逐項寫明哪個數怎麼來的——目標值 0 與容許帶 1.0 都是標準那條平坦容許帶換算來的（依據留在結構化出處欄：ITU-R BS.1116-3 02/2015 §8.3.4.1 Figure 2），較差參考 2.0 是產品選擇。登記簿一條只有一格出處種類，把整條標成標準原文會讓那個產品選擇搭便車冒充有依據。

## 為什麼

取 1.0 而不是 1.06，是因為登記簿裡的尺沒有必要帶一位小數的假精度：換算本身用的是一條理想直線，而真實的容許帶在兩端還會放寬。取 1.0 比換算值嚴一點點，方向是保守的。

兩個數字合起來的行為對得上真實量級：真的參考房量到的傾斜是 +1.46 dB／八度，在這組數字下代價是 0.23，也就是「小瑕疵」而不是不及格；代價到 1 落在 3.0 dB／八度，那等於擬合段兩端相差約 17 dB，確實已經是明顯的染色。維持 0.5 的話同一間房的傾斜會算成 0.48，接近中等瑕疵。

那間參考房**不是**「符合標準」的證據，這一段只拿它當量級的參照：它的傾斜 +1.46 是往上的、原因沒驗（見前一張紙），而且它有一個 75 Hz、−12.8 dB 的深谷，光用現在佔位的峰谷界線就過不了。所以這裡能說的只有一句：一條合理的尺，不該把「今天手上唯一量過的真房間」的傾斜判成接近中等瑕疵，否則這把尺在真實量級上分不出好壞。它是不是好房間，這張紙沒有證據，也不主張。

## 代價

容許帶的依據是換算，不是原文數字；哪天有人拿另一段頻段重算，會得到 2.0 那個比較寬的答案。這件事寫在出處字串與本紙裡，不靠人記得。較差參考 2.0 沒有任何文獻依據，就是產品選擇；它決定的是「多糟算滿分扣」，之後若要用聆聽驗證重訂，開新紙取代本紙。

整條標成產品選擇的代價是：光看出處種類那一格，看不出目標值其實有標準可引，要讀出處字串才知道。這是登記簿一條一格的結構限制，真要分開就得把出處拆成逐欄，那是動契約，另開一題。
