# 引擎樹先搬進來、規矩先別看，再一條一條放進去咬

## 問題

這個 repo 到今天只放規矩，不放產品程式。引擎（做聲學計算的那一大包程式碼，上一代叫 `lib/`）要搬進來，
搬完才解得掉兩張在等對象出現的暫緩卡，也才做得了那張等引擎的流程機票。

搬進來的當下會同時發生兩件事，而且分不開：

1. **樹會很大。** 上一代那棵樹是 174 支 .py、七萬多行、11 個子套件，加上 211 支只依賴引擎不依賴週邊腳本的測試、
   七萬多行（這些數字是搬樹前在上一代那棵已凍結的樹上實查的，不是推測）。
2. **七張現有的規矩卡當場會咬到它**：`style-guard`、`type-guard`、`exemptions-need-expiry`、
   `uv-single-entrypoint`、`refs-and-links-resolve`、`status-page-computed-not-typed`、`secrets-never-committed`。
   第八張 `file-placement-allowlist` 更早一步——根層多一個目錄就紅，樹連進都進不來。

一次做完的話，雲端 `verify`（GitHub Actions 上那個擋合併的檢查工作）會變成一片紅，而那片紅裡混著兩種東西：
**搬壞的**（路徑接不上、資料檔漏了、循環 import）與**本來就會紅的**（引擎的寫法不符合治理層的尺）。
混在一起就分不出誰是誰，那正是上一代事故裡「紅燈太多所以沒人看」的形狀。

## 選項

1. **一次做完**：搬樹、同時把七張卡該修的一起修到綠。一個 PR。
2. **搬樹＋整棵 `src/` 走一筆具名放行**（`[[settings.allow]]`，帶理由與到期日）。
3. **分兩步**：第一步七張卡在掃描面上宣告「這棵樹別看」、零產品程式先合進去；
   第二步搬樹；之後一張卡一個 PR，一條一條把規矩放進去咬。

## 決定

**選項 3。** 分三段落地，順序不能反。

**第一段（零產品程式）**：七張卡各加兩處——`scope`（卡面宣告給人看的掃描面）加一條 `"!src"`、
同一張卡 `[settings].scan_exempt_prefixes`（給程式讀的同一件事）加一條 `"src/"`。
兩邊一一對應，由卡 `scan-scope-has-no-holes`（比對「宣告的掃描面」與「檢查程式實際列舉的檔案集合」那張卡）守著。
同時 `file-placement-allowlist` 的根層目錄白名單加 `"src"`（那是正面定義「准出現這個目錄名」，不是放行），
`pyproject.toml` 的 `[tool.ruff] extend-exclude`（ruff，補 `style-guard` 那四條蓋不到的寫法規則的工具）加 `"src"`，
`[tool.pytest.ini_options] pythonpath`（pytest 的模組搜尋路徑設定）加 `"src"`。
這一段自己要先在雲端綠，證明**排除本身沒有弄壞任何一支檢查**。

**第二段（純搬）**：`src/` 就是上一代 repo 根層的鏡像——`src/lib/`、`src/config/`、`src/scripts/`、`src/tests/`，
不改名、不重排。理由是那棵樹內部有 731 處 `import lib.…` 與 15 處拿 `__file__` 往上數幾層去找 repo 根讀設定檔；
改結構就要改那 746 處，而這一步的目的正是「不改任何東西，先確認搬進來的是完整的」。
搬的清單走版控的檔案列舉（不是整包複製），免得把沒進版控的環境檔一起帶進來。
唯一准動的程式碼是三支頂層引用週邊腳本的檔，改成函式內延遲引用（那棵樹本來就有同一種寫法的先例）。
搬之前在上一代那棵樹跑一次當基準、搬之後在這裡跑一次，**兩次的差才是搬壞的**；本來就紅的照實記進 PR、不修。

**第三段（一條一條放進去咬）**：七張卡各一張票、各一個 PR。哪一張票負責哪一條排除：

| 規矩卡 | 解除的票 | 拿掉排除的當下已知會紅什麼 |
|---|---|---|
| `style-guard` | #113 | 第④條的函式行數與分支數（引擎裡有大函式；幾支未驗，推測） |
| `type-guard` | #114 | 第①層那把尺對一棵沒有自己的型別設定的樹會大片紅（幾筆未驗，推測） |
| `exemptions-need-expiry` | #115 | 第③類：引擎裡 42 個抑制標記（`# noqa` 那一族）一個都沒寫理由與到期日 |
| `uv-single-entrypoint` | #116 | 第②條：15 處拿 `__file__` 往上數幾層的自我定位，卡面已寫死那一條沒有放行的寫法 |
| `refs-and-links-resolve` | #117 | 第①條：程式裡字串常數形狀的設定檔名與資料檔名解析不到（幾筆未驗，推測） |
| `status-page-computed-not-typed` | #118 | 檔名那一條的**誤咬**：叫 `task…`／`status…`／`progress…` 的模組會被當成手寫待辦檔 |
| `secrets-never-committed` | #119 | 第②層：6 個名字帶 `TOKEN` 的字串常數（那一層不管熵、不管長度，本來就是這樣設計的） |

另外兩張票不對應排除，但屬於同一件事：#120（引擎那 211 支測試什麼時候、以什麼形狀進雲端 `verify`——
今天 `testpaths` 不動，它們不在預設收集面上）、#121（三支頂層引用週邊腳本的檔要怎麼收回引擎，
那包週邊腳本反過來又引用引擎兩百多處，是循環）。

## 為什麼

- **紅燈要分得出是誰在叫。** 第一段先綠，等於替第二段立了一個基準：`src/` 進來之後若有任何一支檢查變紅，
  那只可能是搬壞的，不可能是排除沒做對。混在一起做就沒有這個基準，而「一片紅裡分不出誰是誰」
  正是上一代留下來的病。
- **排除寫成掃描面宣告，不是具名放行，是刻意的。** 卡 `exemptions-need-expiry` 的人話自己就分過這條線：
  放行是「具名指向一個個體、把它從已經算出來的違規裡撈出來」，掃描面宣告是「規矩本身的形狀」。
  整棵 `src/` 不是一筆違規，是一整片還沒進入治理的樹；寫成一筆 `[[settings.allow]]` 會讓卡面看起來像
  「有一個已知違規被放過了」，而實際上是「這一片今天沒人看」。兩者對讀卡的人說的話不一樣。
  代價（沒有到期日）寫在下面那一節，不粉飾。
- **鏡像而不是重排，是為了讓「搬壞了沒有」判得出來。** 同時改結構又改位置，
  基準與重跑的差就同時混進「搬壞的」與「改結構改壞的」，又回到分不出誰是誰。
  重排要做就另外一張票、另外一個 PR，而且那時已經有一支雲端驗過的冒煙測試在盯著每一個模組還 import 得起來。
- **一張卡一個 PR，跟這個 repo 立卡的鐵律同一個形狀。** 第三段的每一張票都會逼出一個真的判斷：
  那一條規矩對產品程式碼到底是不是合適的尺。有幾條（檔名誤咬、路徑錨點）今天看起來就不是，
  那要靠一張票上的對話去決定是改卡、改引擎、還是具名放行——不是在搬樹那個 PR 裡順手決定。

## 代價

- **七條排除沒有到期日，只有票。** 卡 `exemptions-need-expiry` 把 `scan_exempt_prefixes` 算資料不算放行，
  所以機器不會問它們什麼時候失效。這是一個**刻意留下的洞**：解除靠人記得去開那七個 PR，
  沒有任何檢查會在某一天把它們變紅。這也不是可以靠改那張卡順手補的——把掃描面宣告一律要求到期日，
  等於要求 `!governance/fixtures` 那種結構性的排除也寫到期日，那條會變成每年要延期一次的噪音。
- **票沒有機器在盯。** 票只能由合進主線的 PR 關掉（那是另一張卡在守的），
  但「這七張票還開著」這件事除了狀態頁上列著之外，不擋任何東西。七張票躺三個月也不會有人紅。
- **第二段合進去之後，引擎那七萬多行就永遠在版控歷史裡了。** 主線不准改寫歷史，
  而 `secrets-never-committed` 是唯一同時掃全部歷史物件的卡——排除的是掃描面，不是歷史。
  所以搬樹那個 PR 本身必須先確認沒有真的機密跟著進來；那一關這次只能靠搬之前對著上一代那棵樹實查，
  加上人看 PR。
- **`pythonpath` 多一條 `src` 之後，`tests` 變成跨兩個目錄的 namespace package**（命名空間套件，
  同一個套件名由多個目錄拼起來）。兩邊的模組名撞到的話，會 import 到另一棵樹的同名檔，
  而且不會有任何錯誤訊息。今天兩邊沒撞（治理層的 `tests/` 底下就那幾支），但這個形狀留著。
- **引擎那 211 支測試這一階段不進雲端 `verify`**，所以「它們在這棵樹上跑得動」這件事，
  在第二段合併的當下只有本機跑過的紀錄，沒有雲端收據。第二段會帶一支雲端會跑的冒煙測試
  （列舉每一個模組、逐一 import），那一支保證的是「import 得起來」，不是「算得對」。
- **三支頂層引用週邊腳本的檔改成延遲引用之後，用到那幾個符號的函式一叫就會炸。**
  這是誠實的壞（不做假實作），但它是一個今天沒有機器看得見的壞——冒煙測試只驗 import，驗不到那幾個函式。

## 拍板

老闆，2026-09-11 對話（票 #111）。分兩步走、鏡像不改名、第一段零產品程式先綠，都是那一次當場拍的。
