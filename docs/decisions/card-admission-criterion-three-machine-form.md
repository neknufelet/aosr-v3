# 立卡判準三的機器形式：守卡本身的卡不參與，只在新候選進門時餵一次

## 問題

票 #217 把判準三、四做成後設測試第七、八回合。第八回合 28 張既有卡全過。第七回合照決策紙字面
「把候選卡的必紅樣本餵給現有每一支檢查」做，結果：261 個樣本目錄 × 29 張卡，每跑一遍 7,569 個子行程、約 420 秒 CPU，
後設測試產收據那一跑再跑一遍，本機一次驗收約七分鐘；而且 `scan-scope-has-no-holes` 咬 27 張卡的樣本、
`check-exit-code-honest` 咬 5 張——不是牙重疊，是守卡本身的卡看到任何一棵帶著卡的樣本樹就會有話說。

## 選項

1. **A1**：守卡的卡不參與；第七回合只對新候選跑（候選＝卡名不在主線 `governance/rules/` 既有名單裡，名單由 git 主線現算、不手寫），既有卡不回頭掃。
2. **A2**：守卡的卡不參與；N×N 全跑，搬到另一個每天跑一次、不擋合併的工作。
3. **B**：每張卡宣告已知重疊，第七回合斷言實際等於宣告；今天要先把 32 組寫進 28 張卡。

## 決定

採選項 1。
- 「守卡的卡」由機器從卡的 `scope` 算：掃描面含 `governance/rules` 的卡，不當被餵的檢查；不手寫名單。
- 「新候選」＝工作樹裡的卡名不在主線 `governance/rules/` 的名單裡；名單從 git 的主線現算（`origin/main` 或 CI 的 base）。
  沒有新候選時第七回合為空、明說「這一跑沒有候選」，不算跳過。
- 餵法跟第二回合同一條路（`--scan-root <case>`、子行程、離開碼）：回 1 才算命中、回 2 不算；控制樣本不算必紅樣本。
- 第七回合要有自己的控制組：假卡＋假樣本走真的子行程路，且要有一題證明「回 2 不算命中」。
- 第八回合照做，但 `scope_kind = "commits"` 的卡分流（掃描面不是路徑，比不了）。
- `card-admission-threshold` 那張紙的「待做」改成：判準四已做（#217）、判準三的機器形式見本紙。

## 為什麼

- 判準三要防的是「新牙其實是舊牙」，進門時問一次就夠；既有卡互不互咬不是這一條要守的事。
- 決策紙自己寫過「新候選准入大約 16 秒，不回頭掃舊卡（那要 4 分鐘）」；字面實作走的正是被否決的那條。
- B 是把噪音登記成規矩，卡面多 32 行沒人會再看，且開了一個無理由、無到期日的白名單格。

## 代價

- 既有卡之間若真的有重疊，這條不會抓；抓它要靠人在 PR 上看。
- 「新候選」的判定依賴主線名單；在沒有 git 的環境（樣本樹當獨立掃描根時）第七回合不跑，由第二回合守。
- 守卡的卡自己立新卡時，這一條對它們沒有咬力。

## 拍板

2026-09-13 早上，老闆在票 #223 回「A1」；助理建議 A1。證據：#217 分支的第七回合命中清單與找碴報告（外部工作區）。
