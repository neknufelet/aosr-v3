# 入口檔行數上限改成 120 行

## 問題

入口檔的全檔行數上限該是多少。第一版的紙拍了一個比較寬的數字，理由是「留空間給後續的卡長」；
第一版的檔寫出來只有七十幾行，老闆讀完的第一句話是太囉嗦。

## 選項

1. 維持第一版那個上限，靠人自己節制。
2. 上限改成 120 行。
3. 上限跟卡數綁在一起算（幾張卡就准幾行，再加一段固定的手寫行數）。

## 決定

選項 2：上限改成 120 行。

理由：上限的用途是**逼人留白**，不是給人填滿。第一版那個數字寬到永遠不會響，於是它守的不是
體積而是一個假設；120 行的位置會讓「規矩節長大」跟「手寫段長大」真的互相排擠，誰要多寫就得
先刪。同一次拍板一起做的兩件事讓這個數字站得住：規矩節一張卡只渲染人話的第一句（一張卡一行），
以及 `AGENTS.md` 改成指路牌、不再是原稿的逐字副本。改完當天實跑：原稿五十行上下，指路牌不到
十行，離 120 還遠——留出來的空間是給後續的卡長的，不是可以長到那裡。

選項 3 不選：一個會自己跟著長的上限不是上限，是一條永遠不會響的規矩。

這個數字的家只有一個：規矩卡 `governance/rules/entry-files-rendered-from-registry.toml` 的
`[settings] max_lines`。不得為了讓某次提交過而改它；要改就再寫一張紙。

## 為什麼

v2 的入口檔從 91 行長到 413 行、九月一個月改 31 次，每次載入都在花注意力，而規則、守衛範圍、
實際程式三邊各自漂（事故 `governance-file-has-no-guard`）。那筆事故自己寫的對策是「生成檔行數
硬上限在生成器內 fail 而非警告」，並舉了一個明顯更緊的數字。第一版的紙把上限訂寬，是為了
「還有很多張卡要進來」；一版寫完就發現：寬的上限不會讓人寫短，只會讓人不必選。

## 代價

規矩卡繼續加下去的話，規矩節會逐張逼近這條線（今天一張卡一行）。到那一天要選的是「把手寫段
再砍」或者「再寫一張紙調上限」，不是在卡上把數字往上挪。這張紙只改數字，第一版那張紙的其餘
規格（規矩節生成、標記包住、CI 重生比對、手改即紅）照舊有效，所以 `supersedes` 留空。

## 拍板

老闆，2026-09-10 對話：「先把 CLAUDE.md 預設上限 120 行」。同一次對話一起拍的還有兩件事，
寫在規矩卡上、不另寫紙：手寫段大砍到二十幾行，以及 `AGENTS.md` 改成指路牌。
