# 低頻拖尾在擺位階段先做模態診斷報告，不進正式排名

## 問題

#352（低頻拖尾）接進評分的第二題：擺位搜尋時（房間與材料固定）要不要把低頻拖尾算成擺位的代價、進正式排名。

- 示範房（2026-10-06，#352 第二題留言、工作區 352-scoring-q2）：計分範圍內 168 個共振有 165 個長過 `low-frequency-decay-reference-curve.md` 的目標線。單一模態的本徵 T60 不隨擺位改變；擺法改的是哪些共振在聆聽位置被激發得強，接收點的合成衰減也可能跟著變。
- 想把它算成一個擺位分數，試了四種代價形式，名次都會被分群、頻段與合成方式的選擇翻掉：一串重疊共振挑誰當代表；「共振分得開」的界線畫在 64 還是 96 Hz（兩種排法順序相反的配對占 64%）；頻帶邊界整體移 1/6 八度（占 45%）。這些比例只表示兩種算法不同意，不表示比隨機排名更不準。
- 限制：只有一間六面同阻抗的房、一批集中在前牆附近的候選。

## 選項

- A：本階段先做低頻模態診斷報告，不進正式排名；材料會變的階段再檢查接入條件。
- B：現在就接進排名，用主對話挑的預設（96 Hz 以下逐群、強弱相對聆聽位置的低頻平均、加總），接受名次跟著這個預設走。

## 決定

採 A。

1. **不進排名、不碰評分契約。** 低頻拖尾不放進候選的評估包、不進類別註冊表；評分契約裡低頻拖尾那一格維持空殼。排名、比較身分與搜尋篩選分數一律不變，既有控制組逐位不變。
2. **診斷是另一份產物**（`src/aosr/reporting/modal_diagnosis*.py`，綱要 `aosr.modal_diagnosis.v1`），分兩層：
   - 房間層：每個解一列（種類、頻率、複數 ω、T60、Q、所屬重疊群；只有共振進群）、每個重疊群一列（成員、頻率上下界），以及求解自檢摘要（保證找齊的衰減高度、各段個數對 Weyl）。
   - 擺位層：每個（喇叭、座位）對每個共振存兩個絕對大小：它自己的大小，以及它所屬整群在它的頻率上複數相加的大小。只存絕對大小，不存相對 dB 或「相對座位低頻平均」這類會被當成代價分母的量。
3. **群組是群組。** 不挑代表成員，不給整群一個 T60 或一個超出量；群的呈現是成員數、頻率跨度、T60 範圍、超過目標線與參考線範圍外的成員數，以及整群大小沿成員頻率的剖面。
4. **四種狀態分開表示，各帶原因，不用零分冒充通過**：已完成診斷但不計分、未計算、失敗（保留建網格、求解、展開、查位置或快取讀寫丟出的原文，不退回別的解法、不重試）、範圍外（房型或材料不在模態能力範圍，例如阻抗不是有限正實數）。逐共振的「參考線範圍外」（32 Hz 以下、250 Hz 以上）在模態表上逐列標未評估，超出量是空的，不混成整份的狀態。
5. **超出量讀回時才算。** 存的是頻率、T60、Q、複數 ω、群組；目標線與超出量在讀回時用當下的品質登記簿算（`low-frequency-decay-reference-curve.md` 的參考線），登記簿改值不必重解，也不把登記簿拖進任何身分。「激發得強」只排序、不設 dB 切線；相對 dB 只在讀回時現算，寫明是相對同一喇叭到同一座位最強的共振。
6. **不換物理身分。** 模態程式不進物理段的載入閉包，物理身分不變。診斷自帶模態身分 `modal-v1:<雜湊>`，照物理身分的做法收兩樣：從診斷入口模組算的載入閉包程式雜湊，以及執行環境（Python 版本、平台、求解程式庫版本，跟物理身分同一份清單）。
7. **同房同材料只解一次。** 快取的鑰匙是房間三邊、六面阻抗、密度、聲速（都存 float.hex）、正式網格三參數（上限頻率、每波長格數、種子，從程式設定讀）與求解選項全部欄位；不含頻率軸，也不含喇叭與座位位置。房間層記下解它那張網格的指紋。讀快取時鑰匙、模態身分、內容雜湊或網格指紋（跟照鑰匙重建的網格比）不符，就當成沒有快取、重解覆寫（這是讓快取作廢，不是換解法）；解完先寫快取再做展開與查位置，後面丟錯也不用重解；寫入先寫暫存再改名，不留半份；同一把鑰匙重寫時清掉舊的形狀檔。快取資料夾由呼叫端給，路徑必填。聲速與密度由呼叫端從物理常數設定檔讀。
8. **材料階段重新檢查代價接入條件，不預先承諾到那時就自動計分。** 這次不再為了選 A 擴增一輪算法搜尋。
9. **分三支合併請求落地**：核心（本紙與診斷零件，不接網頁與搜尋）→ 網頁與命令列（結果帶選填的診斷欄位、舊結果讀成未計算；結果頁兩層與四種狀態；能力表加一節試驗中）→ 搜尋（房間層一次、擺位層用擺位表那組方案；報告加一段，「尚未評估」改寫狀態）。

## 為什麼

- 理由只限這間示範房與這批候選：目前試驗的代價形式對分群、頻段與合成方式高度敏感，還不足以選定正式排序方法。這不是說低頻拖尾對擺位沒有價值；未來可能建立有效的擺位指標，這條路保留。
- 先前「干涉造成，所以不是拖尾」的推論不成立：單一模態的本徵 T60 不隨擺位改變，但接收點的合成衰減可能改變；取消交叉項是在改變評估量，不能拿「回到個別 T60 範圍內」證明哪一種算法對。
- 放進評估包會被排名層判成代價未算、候選掉進未評估，搜尋的原方案也會缺類；進類別註冊表會讓報告說「用到的尺全部校準完」。所以診斷放在評估包外面。
- 群組不挑代表：大型重疊群（示範房 160～250 Hz 一串）挑哪一個成員代表，正是翻掉名次的選擇之一。
- 超出量讀回時算、診斷自帶身分：登記簿改值時不用重解（一次求解在示範房約 505 秒），物理身分也不會因為診斷程式改了而變、讓舊結果全部要重算。

## 代價

- **時間與記憶體**：示範房 30ρc 一次求解約 505 秒、記憶體峰值約 5.0 GB（2026-10-05 實測，工作區 352-modal-participation 的 z30-timing.json）；網頁上換一個新房間或新材料就要等這一次。同房同材料之後每份多約 5～6 秒：建網格 0.45 秒、組矩陣與核對形狀 4.9 秒、查位置 0.02 秒（同一份實測），另加讀快取驗雜湊與解壓（未量）。老闆網頁那間 4ρc 用現行程式沒跑過，未驗。搜尋每次多一次求解，約佔正式搜尋 3 小時的 4.6%（推測，未驗）。另一條路是改成按需（按鈕才算），網頁那一支再定。
- **磁碟**：一份快取存全部模態形狀，示範房約 0.3 GB（估算，未實測寫檔）；不同房間或材料各一份，沒有自動清理上限，要人看著。
- **快取鑰匙沒收的東西**：模態載入閉包會讀 `fem_lane.toml`（形狀與位置搜尋的設定，不影響模態求解），不進鑰匙也不進模態身分；考卷釘住閉包只讀這一份，多讀別的資料檔就紅，那時要決定它進鑰匙、進身分還是明列放行。`fem_lane.toml` 本身多一個會影響求解的欄位，這一格擋不到。
- **程式庫升版**：求解程式庫、Python 或平台一換，模態身分就換，所有模態快取作廢，每間房重解一次（示範房約 505 秒）。
- **報告不等於排名**：擺位搜尋的名次完全不看低頻拖尾；讀報告的人要自己看哪一個擺法把超過目標線的共振激發得強。
- **未接入的部分**：核心這一支不接網頁、命令列、搜尋；在三支都合之前，網頁與搜尋報告照舊寫低頻拖尾「尚未評估」。
- **限制沿用**：求解自檢的保證高度與 Weyl 對照保留 #661 的限制，在房間層照實帶出；保證高度為零時最低 T60 寫空的，不寫無限大。

主對話補的落地細節（不是老闆原話）：
- 第 1 條：「不納入正式排名」怎麼落到程式上（不放進評估包、不進類別註冊表、評分契約那一格維持空殼、比較身分與控制組不變）。#671 四格的 A 原本寫「排名層帶著它但不計分」，改成放在評估包外面，是主對話依開工前的摸底改的。
- 第 2 條：診斷是另一份產物與綱要名；房間層存哪些欄位（含求解自檢摘要）；擺位層每個共振存自己的大小與整群複數相加的大小，不存相對 dB 與「相對座位低頻平均」。
- 第 3 條：不給整群一個 T60 或超出量；群呈現哪些欄位與整群大小的剖面。
- 第 4 條：每種狀態各帶原因；範圍外的例子；逐共振的參考線範圍外逐列標。（「不退回別的解法、不重試」是專案既有規矩。）
- 第 5 條整條：超出量讀回時才算、登記簿不進任何身分、不設 dB 切線、相對 dB 只在讀回時現算。
- 第 6、7 條整條：模態身分（含執行環境）、快取鑰匙、網格指紋與讀寫規則。這幾條是 2026-10-06 兩角度審查之後補的（審查實測過：網格對不上時舊做法會每次都判失敗、永遠不重解）。
- 第 9 條：分三支落地；代價段的「改成按需（按鈕才算）」是主對話提的選項，沒有拍板。
