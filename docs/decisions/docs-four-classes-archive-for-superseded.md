# docs/ 加第四類封存區：被取代的決策紙必須搬過去，活的目錄只放還算數的決定

## 問題

決策紙的規矩是舊決定不改、開新紙取代，舊紙標 `superseded` 留著當歷史。到 2026-09-15 主線有 57 份決策紙、其中 10 份已被取代，
而標頭卡登記的上限是 60 份。治理層盤點那一輪要再加幾份、晚期混響改類別又要加，這一輪一定撞線；撞了臨時提上限就是
上一代事故 `governance-numbers-changed-on-a-whim` 的形狀。老闆在票 #313 說：「60 個一定會超過，收也一定要收」。

`docs-three-classes.md` 的代價那一段早寫了：將來要開第四類就改那張紙。這張紙就是那一步。

## 選項

- **A：真的收走**。多一個封存區 `docs/archive/`，被取代的紙搬過去；活的目錄只放還在生效或待拍的決定；上限數活的；
  機器守「死的不准留在活的目錄、活的不准躺在封存區」，搬不搬不靠人記得。
- **A′：檔不搬，數份數時跳過標 `superseded` 的紙**。少改兩張卡，但活的目錄裡活的死的混在一起，讀的人得先看狀態欄。
- **B：上限提到 80**。最省事，下次滿了再提，等於沒有上限。

## 決定

採選項 A。

1. `docs/` 四類：`decisions/`（活的決定）、`archive/`（被取代的決定）、`design/`、`cairn/`。平行不分層、限種類、算得出來的不存檔，
   三道柵欄照 `docs-three-classes.md` 原樣。封存區只收決策紙，不收過程紀錄。
2. 規矩卡 `decision-paper-structure` 加第八條：標了 `superseded` 的紙必須住 `docs/archive/`；`docs/archive/` 裡只准有標了
   `superseded` 的紙；取代關係跨兩層找；兩層同一個檔名即紅。開新紙取代舊紙的那支合併請求就得把舊紙搬走，不搬雲端紅。
3. 封存的紙一字不改，只搬；唯一例外是紙裡指到別份決策紙的路徑（那份也搬了）要跟著改，不然路徑解析卡會紅。
4. 標頭卡 `doc-frontmatter-and-dates`：`decisions` 上限 60 不動，數的是活的那一層；`archive` 另設上限；總量上限跟著提，
   仍比各類相加緊（數字住卡上，這裡不抄）。
5. 檔案白名單卡 `file-placement-allowlist` 的 docs 那一層加 `archive`。
6. 讀舊決定去 `docs/archive/`；活的紙的 `supersedes` 欄仍寫舊紙的檔名，不帶目錄。

## 為什麼

- 活的目錄只放還算數的決定，讀的人不用先看狀態欄；上限數的是活的，永遠不用再提。
- 收不收靠機器：上一代封存了 715 份還是長回去，因為封存靠人事後盤點；這裡把「取代就得搬」做成同一支合併請求的紅綠燈。
- 不選 A′：它把「死的不算」寫進計數規則，但檔案還混在活的目錄裡；三類那張紙的病根是「有用的被埋掉」，混著放正是埋的開始。
- 不選 B：上限一提就不是上限。

## 代價

- 三張卡各動一格或一條牙，搬 11 份紙（含這張取代掉的 `docs-three-classes.md`），指到它們的路徑要跟著改。
- 之後每次開新紙取代舊紙，同一支合併請求多一個 `git mv`；忘了會紅，紅得出來就是這條牙在的證據。
- 封存區的紙不再被 `no-model-names-in-entry-files` 那張卡掃（它只掃 `docs/decisions/`）；封存紙是歷史，不是開工會載入的檔。
- 其他卡或程式若以 `docs/decisions/<檔名>` 指到被取代的紙，搬家後要改指 `docs/archive/`；今天有五處，這一支一起改。
