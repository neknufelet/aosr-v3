# 鏡像法 JAX 版對現有雙精度實作的尺：2^-48 暫定，單精度只量不登記

## 問題

第三階段要對牆面材料取梯度（#562）。`docs/decisions/optimization-stages-room-with-positions-then-layout-then-zoned-materials.md` 表二鏡像法那一列定了：幾何的路徑、距離、到達時間與入射角用中央處理器雙精度，第三階段用 JAX（自動微分計算庫）在顯卡上用單精度。第三階段幾何不變、只改表面阻抗，所以路徑表固定，只有每條路徑的反射乘積（每次反彈 `R=(Z·cosθ−ρc)/(Z·cosθ+ρc)` 連乘）隨阻抗 Z 變。

新的 JAX 版在 `src/aosr/physics/amplitude_jax.py`，它要跟現有 Python 雙精度實作（`src/aosr/physics/amplitude.py`、`src/aosr/physics/wall_reflections.py`、`src/aosr/physics/totals.py`）對得上。現有的逐路徑振幅契約（`docs/decisions/precision-contracts-geometry-energy-amplitude-fem.md`，基底 2^-21）是給上一代單精度答案用的，太寬，守不住「同一條公式改寫成 JAX」這件事。所以要定 JAX 版拿什麼尺比，以及單精度那條怎麼處理。

## 選項

- **A**：JAX 雙精度對現有 Python 雙精度另立一條尺，用量到的差留餘裕訂成 2^-n；同一個基底餵進現有的五支界線函式（反射乘積、路徑壓力、總壓力、反射能量、直達能量），不另寫新公式。單精度對雙精度只量、不登記。
- **B**：JAX 版直接沿用現有逐路徑振幅契約（基底 2^-21）。單精度也過得了，但雙精度改寫錯一個捨入量級以上的錯都抓不到。
- **C**：要求 JAX 雙精度跟現有實作逐位相同。量到的結果不是逐位相同（見「為什麼」），只能靠逐一模仿 CPython 的複數除法與加總順序，等於把 JAX 版寫死在一種運算順序上。

## 決定

採選項 A。

- 登記簿 `blueprint/precision_contracts.toml` 新增 `amplitude_jax_vs_python`＝`2^-48`，單位 absolute，**暫定**。比的是 JAX 雙精度對現有 Python 雙精度實作。
- 同一個基底餵進現有五支界線函式：反射乘積每分量絕對差（`reflection_tolerance`）、路徑壓力相對差（`pressure_tolerance`）、總壓力的平方相加開根（`total_pressure_tolerance`）、反射能量（`reflected_energy_tolerance`，地板取同一個基底）、直達能量相對差（`direct_energy_tolerance`，取同一個基底）。裁判與變異考卷在 `tests/engine/test_amplitude_jax.py`。
- 雙精度只在冷子行程裡量：同程式的考卷跑在 JAX 預設精度（雙精度關），雙精度輸入會被悄悄降成單精度。
- 單精度對雙精度只量、不登記。顯卡單精度另立一把尺，等接進第三階段計算時照 `docs/decisions/precision-contract-rulers-live-in-one-registry.md` 登記，這張紙不訂那個數字。
- 設計決定：相位因子 `exp(−i·2πf·τ)` 與 `1/dist` 只跟幾何有關，在中央處理器上用雙精度先算好（跟現有 `path_pressure` 同一種寫法），當成路徑表常數；單精度那條在進場時才轉成單精度，所以沒有「ωτ 先切成單精度」的相位誤差。這跟上一代的單精度做法不同。
- dtype 跟著輸入走：阻抗是單精度複數就整段單精度，是雙精度就整段雙精度；這支程式不碰 JAX 的全域設定。

## 為什麼

2026-10-28 在本機（中央處理器、JAX 0.10.1）實測，四組三階 63 條路徑的案例：兩組振幅答案的輸入（flat、varied，6 個頻點）、同一間房配 220 點幾何路頻率軸與隨頻率變的阻抗（dense）、兩面構造牆的逐角阻抗（construction，對照現有 `WallReflectionSources.apply`）。

JAX 雙精度對現有 Python 雙精度：

| 案例 | 反射乘積絕對差 | 壓力相對差 | 總壓力相對差 | 直達能量相對差 | 反射能量相對差 |
|---|---|---|---|---|---|
| flat | 0 | 0 | 4.4e-16 | 4.3e-16 | 1.3e-15 |
| varied | 2.8e-17 | 2.2e-16 | 3.9e-16 | 4.3e-16 | 1.2e-15 |
| dense | 4.4e-16 | 8.5e-16 | 2.0e-15 | 3.4e-16 | 6.5e-15 |
| construction | 1.1e-16 | 4.2e-16 | 3.0e-16 | 3.4e-16 | 6.0e-16 |

- 四組都不是逐位相同：dense 的反射乘積 13860 格裡有 4822 格逐位相同，flat 全部相同。
- 用界線函式算「差÷界線」的最大值：基底 2^-48 時最多用到 0.125（dense 的反射乘積；直達能量 0.121）；2^-50 時最多用到 0.5；2^-52 時已有格子超界。所以取 2^-48，留 8 倍餘裕給別台中央處理器與別的函式庫版本。

單精度對雙精度（只量）：

| 案例 | 反射乘積絕對差 | 壓力相對差最大（中位數） | 總壓力相對差 | 直達能量相對差 | 反射能量相對差 |
|---|---|---|---|---|---|
| flat | 4.8e-08 | 4.8e-06（9.4e-08） | 7.5e-07 | 1.6e-07 | 3.6e-07 |
| varied | 7.5e-08 | 5.0e-06（9.9e-08） | 6.5e-07 | 1.6e-07 | 3.3e-07 |
| dense | 1.8e-07 | 2.4e-06（1.0e-07） | 2.3e-06 | 4.3e-07 | 2.3e-06 |
| construction | 1.6e-07 | 2.0e-06（1.3e-07） | 2.0e-07 | 2.4e-07 | 1.0e-06 |

- 壓力相對差的最大值出在反射乘積很小的格子（界線公式裡 1/|反射乘積| 那一項），不是相位造成的，因為相位是雙精度常數。
- 拿上一代的尺（基底 2^-21）量單精度：四組都沒超界，最多用到 0.89（dense 的直達能量）。這只是量測，沒登記、沒斷言。
- 梯度跟中央差分比（步長取 |Z| 的 10⁻⁶）：最大差除以梯度尺度，varied 36 格是 9.2e-10，construction 18 格是 4.5e-10。eager、jit、vmap 三種跑法在雙精度與單精度下都逐位相同。
- 植錯九種（反射係數分子分母對調、不乘 cos、相位共軛、反射能量算進直達、不遮沒用到的反彈格、強制雙精度、構造牆用同一個角、同牆多次反彈只乘一次、相位角用單精度）全部被考卷抓到。

## 代價

- 數字只在一台中央處理器上量過；別台中央處理器或換函式庫版本時會不會吃掉 8 倍餘裕，未驗。
- 沒在顯卡上量：本機的 JAX 沒有顯卡版，單精度數字全是中央處理器上的；顯卡單精度的差距未驗（推測同量級），那把尺另立。
- 分格材料（逐反彈查格）不支援，路徑表遇到就拒收。
- 路徑表是編譯常數：jit 時當閉包帶進去，換一張表就要重新編譯；只能對阻抗做 vmap，不能對路徑表做。
- 構造牆的逐角阻抗由 `bounce_impedances_from_sources` 在中央處理器上用 numpy 求好再交進來，梯度不穿過它；對構造參數（厚度、流阻）一路微分回去，要等材料核心直接接進 JAX 那一段。
- 速度與記憶體沒量：第三階段一輪用 jit 會快多少、顯卡上吃多少記憶體，都不知道。
- 梯度只驗了一種目標（總壓力模平方和加反射能量）對 Z 的微分；構造參數（厚度、流阻）一路微分回去沒驗（`bounce_impedances_from_sources` 走 numpy，見上面那條）。沒用到的反彈格不管填什麼，梯度都有限而且恰為 0，有考卷守。
- 總壓力用 JAX 的加總，順序跟 Python 逐條相加不同，只保證在尺內，不保證逐位相同。
- 變異考卷只推了反射乘積與路徑壓力兩種量；總壓力、直達能量、反射能量三支界線在裁判裡被改鬆，這支變異考卷抓不到。

## 拍板

- 材料與三路一起放顯卡：2026-10-11，老闆在對話裡原話「然後我們材料一定要在顯卡,目前ism/晚期混響都已經是,之前也有測過fem的方式有機會放到顯卡,全部丟一起跑」（出處 `docs/decisions/material-stage-tmm-gpu-single-precision.md` 拍板段）。
- 鏡像法幾何用中央處理器雙精度、第三階段用 JAX 在顯卡上單精度：`docs/decisions/optimization-stages-room-with-positions-then-layout-then-zoned-materials.md` 表二鏡像法那一列，老闆在票 #285 回 A。
- `2^-48` 這個數字、「單精度只量不登記、顯卡單精度另立尺」、相位用雙精度常數先算好，都是主對話依量測判斷（#562），老闆沒逐字拍。
