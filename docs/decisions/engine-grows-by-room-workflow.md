# 引擎依可操作的房間流程逐步重建

## 問題

按舊子套件逐包對齊，能完成個別函式，卻沒有把「輸入房間、計算、看到結果」列為近期交付。
使用者希望改從一個可重跑的參考房間開始，依功能逐步重建、重構或重寫。

## 選項

1. 繼續以舊子套件為交付單位，補齊其公開函式與相容測試。
2. 以可操作功能為交付單位，只實作該功能需要的部分，逐階段擴充。

## 決定

採選項 2。一個有明確輸入、輸出及驗收的功能為一階段，票面列出承諾與邊界。
取代前案的整包交付義務；不再以完成全部舊公開函式作為每個功能的前置條件。

保留前案的來源隔離：v3 只有新家 `src/aosr/`，不引入舊引擎樹；原料使用
`v3-donor` 凍結唯讀來源。保留已完成成果與既有測試契約，不因轉向刪除或放寬期望值。
現行分層、規矩與雲端 `verify`（擋合併的驗證工作）繼續適用。

第一階段只建立參考房間，不實作 v3 產品計算：

- 用凍結 v2 跑一間長方形房、一個聲源、一個接收點，取得直達聲與各面一次反射。
- 保存完整輸入、單位、座標、材料假設、頻率、聲速與時間定義，及版本、環境、
  可重跑命令、退出碼、原始輸出與資料雜湊；具體參數由該階段選定並記錄。
- 用獨立幾何計算核對路徑身分、距離及到達時間。v2 是相容性參考，不自動等於物理真值。
- 在候選實作前，依各量定義與參考證據訂明精度契約；不能看到候選差異才放寬。
  涉及更改既有公開契約或驗收門檻時，另按現行決策流程處理。
- 跑不起來或核對不一致，先診斷並保存可重現的窄阻塞；不得當作成功完成、
  擴大搬遷代替交付，或靜默換一套求解器當參考答案。

第二階段再建 v3 的可修改輸入 → 計算 → 路徑與到達時間呈現 → 參考差異流程。
參考資料與第一階段驗收成立後，才依其結果界定實作範圍。
振幅、多次反射、計分、最佳化及外部模擬器交叉驗證後續另排；未驗證者不宣稱已驗。

## 為什麼

每階段都對應使用者看得到的能力，能用少量明確案例建立完整計算路徑，
避免舊資料夾邊界持續擴大相容性工作。參考重跑與獨立幾何核對分別回答
「是否保留指定行為」與「簡單物理關係是否成立」，兩者不能互相代替。

## 代價

不承諾完整覆蓋舊子套件；每階段必須明列尚未支援的功能。
單一參考房間只能支持其案例範圍，後續新增功能與輸入範圍須補相應驗收。
第一階段交付資料與證據，尚不是可操作的 v3 計算器。

## 拍板

2026-09-12，使用者提出回到基本房間流程、依功能逐步重建；助理建議先完成
決策、工作票與交接的轉向，再做 v2 參考房間，使用者回覆「恩」同意執行交接。
上述階段邊界是本次交接的具體化，不把助理的執行細節冒稱為使用者逐字指示。
