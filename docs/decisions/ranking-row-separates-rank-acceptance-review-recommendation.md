# 排名列把名次、外部驗收、複核狀態、推薦狀態分成四格

## 問題

#445 之後，踩到峰谷警戒的候選不淘汰、照樣排名。排名表只看得到「第 1 名」，讀的人會把它當成已經驗收完的最終推薦；可是那根 +12 dB 的峰還沒加密確認。另一頭，如果把警戒塞進外部驗收，噪音、預算、施工都通過的方案會被說成驗收沒過，也是錯的。

## 選項

1. A：第一名帶警戒時，整體驗收不回「通過」（票身原本寫的做法）。
2. B：不動外部驗收；三個問題拆開各記一格——排名第幾、有沒有已知問題直接不合格（外部驗收）、還有沒有事情沒確認完（複核狀態）——再加一格推薦狀態。

## 決定

採 B。可排名列（`RankableRow`）多三格，型別住 `src/aosr/scoring/recommendation.py`：

- `review_status`：受控字串 `clear | pending`。有任何一條複核警戒就是 `pending`；今天沒有解除機制，警戒一律算未解除。
- `recommendation_status`：受控字串，今天只有 `not_final` 一個值——還沒有任何機制能把一列升成最終推薦。
- `not_final_reasons`：非空的受控原因清單，固定順序：`review_pending`（有未解除警戒）、`external_not_checked`（這一列外部驗收未檢查）、`calibration_baseline`（這份結果的校準狀態是基線）、`no_finalizing_process`（升成最終推薦的機制還沒有，永遠在）。

外部驗收（列上的 `external_acceptance` 與表頭的 `overall_acceptance`）的意思不動：只由外部底線決定，警戒不改它。淘汰、未評估、不可同表三區不加這三格（沒有名次就沒有推薦可談）；淘汰列原本帶的警戒照舊。

## 為什麼

- 外部驗收回答的是「有沒有已知問題直接不合格」；待加密的峰是「還沒確認完」，不是不合格。混成一個狀態，兩個問題都答錯。
- 狀態用受控字串不用布林值：以後加「已解除」「經認可放行」之類的狀態不必重做契約。
- 原因列清單而不是只給一格：讀的人要知道這一列為什麼還不是最終推薦，而且原因可以同時好幾個。

## 代價

- 今天每一列都是 `not_final`，連沒有警戒的那一列也是；推薦狀態這一格暫時分不出列與列，區分靠 `review_status` 與原因清單。
- 誰可以解除警戒、要什麼證據、加密到多密、人工能不能蓋過，都還沒有；等 #435 與嚴重峰谷判準成熟再開一張票。
- 前台畫面那句人話（「目前排名第 1 ⚠ 峰值警戒尚未解除……尚不能列為最終推薦」）不在這一刀；這一刀只給機器讀的資料，畫面文字等前台那一題。
- 排名輸出多三格。沿用 #445 的處理：同類契約變更不升版本字串，交換格式版本另由 #411 決定。

## 拍板

2026-09-23，老闆在 #449 的看法（摘要，原話要點）：不要動外部驗收的意思——噪音、預算、施工都通過而音色有一個待加密的 +12 dB 峰時，外部驗收沒有失敗。三個問題拆開、不混成一個狀態；輸出四格 `Ranking: Rank 1`／`External acceptance: Passed`／`Review status: pending`／`Recommendation status: not final`。資料結構不要只做布林值：`review_status` 一開始就是受控狀態 `clear | pending`。解除機制晚一張票。
