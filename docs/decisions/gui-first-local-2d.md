# 第一版介面先做本機網頁與二維圖

## 問題

#516 要把房間方案變成能操作的入口。需決定跑在哪裡、先畫到哪一層，以及輸入、存檔、計算各由誰負責。
四塊範圍「房間與擺位輸入、按鈕計算、聲學結果、方案比較與保存」是覆核者文字；老闆回「大致覺得可以」，不是逐條拍板。

## 選項

1. A：這台電腦跑小伺服器，用瀏覽器開本機網頁；第一版只有老闆自己用。
2. 二維圖先畫平面圖與側面圖；三維圖和網格另排。

## 決定

採本機網頁與二維圖。介面只收輸入、下指令、顯示；計算與評分一律走引擎。JavaScript（網頁腳本）只畫伺服器給的 JSON（資料物件），不寫聲學公式、分數或基準線。這是「介面不准再寫公式、分數或基準線」今天唯一的防線。

伺服器預設只聽 127.0.0.1。要從自己其他裝置直接連，啟動時用 `--listen` 改聽這台的 Tailscale（私人網路）位址：只收 127.0.0.1 或 Tailscale 的 100.64.0.0/10，不收 0.0.0.0 與區網位址；再用 `--allowed-host` 列出瀏覽器會帶的名字（機器短名、全名、位址），127.0.0.1 與 localhost 之外沒列的一律拒收，萬用字元與埠號不收。瀏覽器打機器名加埠號就能開，不用任何管理員指令。

聽在 Tailscale 位址本身擋不住區網與容器：Linux 會把任何網卡收到、寄給本機任一位址的封包照收，2026-09-28 查時這台的防火牆也沒開（ufw 設定 ENABLED=no）。所以聽 Tailscale 位址時，伺服器另外只接受本機與 Tailscale 網段來的連線（扣掉 Tailscale 不發、自己也不擋的 100.115.92.0/23），其他來源回 403，也不信任轉發標頭。這一道擋得住收不到回覆的偽造者；區網裡冒充 100.x 來源的連線，還要靠 Tailscale 自己的防火牆規則（要 root 才看得到，未驗）。2026-09-28 從老闆的另一台 Tailscale 裝置實測連得上。畫面仍照電腦螢幕排，手機版面不在這一版。

方案檔與結果檔存在 repo（程式庫）外；伺服器啟動時拒絕 repo 內的資料路徑。結果比較用物理身分判同一套物理（#577；收哪些見 `shared-search-flow-v1-stage-two-subset.md` 第九節第 2 條）。整支程式的計算指紋（量 `aosr` 套件內所有檔案的位元組，只扣 `gui` 與 `__pycache__`，加實際讀入的能力表內容、Python 版本與正式依賴版本）用來判網頁伺服器過期、命令列計算途中程式被改（寫檔前再量一次），也存進結果檔備查；它不參與讀回分級。
只扣 `gui`，是因為分層卡禁止計算層 import gui；那張卡只守 import 語句，執行時讀檔等跨層方式不在它的範圍（已知缺口）。命令列在量第一次指紋前不載入計算程式；之後的改動由寫檔前第二次量測攔下。`engine_commit`（引擎提交識別）仍由啟動的人給完整四十位，只作備查標籤。
伺服器啟動時記下指紋；開著時若程式更新，結果頁與比較頁先不開、重算先擋下，畫面寫明要重開伺服器。計算另開行程與行程組，停止時終止整組。第一步只顯示已跑秒數、參考約六分鐘與錯誤原因（計算程式自己印的英文輸出收在技術細節，結果檔路徑與計算代號不上主畫面）；結果頁在第二步。

表單提供房間長寬高、六面正實數阻抗、選填散射、喇叭與座位座標、主位 z 座標和兩種既有聲源模型；周圍點要逐點改。`feature_match_tolerance_hz`（特徵配對容差）沿用範例考卷的 10 Hz，未查證為產品預設。聲速與密度由範例方案預填。

本步沒提供 `reflection_order_k`（反射階數；只有預設 K=3 有數值考卷）、`low_frequency_axis`（低頻頻率軸；驗證軸耗時未量）、三維圖、拖曳即時重算、帳號，也不做結果頁。

第二步加上結果頁。頻響、各類代價、警戒、逐帶殘響、反射和聆聽區只顯示引擎已算出的資料；
聆聽區逐點差值直接走評估器同一段配對與距離程式。結果檔讀回重評被拒收時，畫面給原因與重算按鈕，
重算從結果檔的方案快照另存一份交給現行引擎，與現在的存檔方案無關。聆聽區按方案實際周圍點距離顯示最遠值；其他座位沒有納入，不作品質暗示。

「修到能拿來判斷」已落地的預設規則：有正常完成的結果（完成，或沒有計算紀錄的舊結果）或正在算的方案不得同名改內容，改過的設定另存新名字；改欄位時標示舊結果；重新整理只接回正在算的計算。這些是主對話採用的預設，老闆可改。

第三步比較頁方向來自覆核者文字：位置並排、頻響疊圖、分項並列表；預設比較 A 左聲道主位與 B 左聲道主位，兩邊共用刻度、不各自對齊音量；一句摘要只用現有欄位組，低頻拖尾標「尚未評估」；摘要另寫哪一份總代價較低、差多少（越低越好），評分尺度沒正式校準、只看相對好壞，兩份有沒解除的複核警戒時寫明不能當最終推薦；先匯出曲線圖片與結果資料。施工分步：先交伺服器比較資料，再做畫面、位置並排與匯出。資料端點列出方案逐欄差異、座位與聲道指紋、原值疊圖聯集軸、分項並列、相容時的同表排名與校準字句；拒收時一次列出全部原因。同版規則依 #541 改為計算指紋，#577 再改為物理身分加讀回分級。

#566（老闆 09-30 交代「保留失敗產物供診斷，不讓它鎖住方案名稱。比較可保留診斷查看，但必須明顯標示失敗，不呈現為正常完成的方案優劣結論」）：計算回報失敗、但結果檔已寫出的那一筆留作診斷、不凍名字；清單在方案代號底下標狀態，結果頁與比較頁頁首寫警語，比較頁與兩種表格、曲線圖片匯出都標出哪一份沒有正常完成、不下哪一份比較好的結論。已停止、計算中同樣當沒有正常完成，是主對話的判斷；沒有計算紀錄的舊結果照舊當完成，計算紀錄讀不出或狀態認不得也照沒有紀錄處理（紀錄讀得動、只是錯誤輸出檔不在時照紀錄寫的狀態）。

#570（老闆 09-30 問「清單可以清除嗎」「刪掉不能嗎」、要「加上一個備份按鈕」；主對話給兩個都不刪的選項——封存或整份備份——老闆選封存）：結果清單每一列一顆「封存」，把那一筆的結果檔搬進資料夾裡的 archive，清單底下「已封存」一區每筆可以搬回。要時可以搬回是老闆選的那個選項本身；只給不刪的選項、計算紀錄與重算快照一起搬、搬到一半失敗就搬回原處、正在計算的不能封存、有正常完成結果的方案封存後照樣凍名字、搬回做成畫面上的按鈕，這些是主對話的判斷。

畫面檢查分兩層。第一層是雲端的畫面考卷：用無頭 Chromium（Chrome 的核心、不開視窗）開本機網頁，驗事先想得到的壞法——每一頁打得開、瀏覽器沒報錯、圖上真的有線、點了有反應、沒有未格式化的數字或空值字樣；瀏覽器在 verify 考卷前那一步安裝，缺了就紅、不跳過。
第二層是每次改畫面都在本機截圖、由人親眼看，抓事先想不到的（字擠在一起、難看、顏色分不清），截圖存在工作資料夾當證據。第一層只能擋已知的形狀；新形狀第一次靠第二層抓到，之後寫進第一層。

## 為什麼

本機單人使用符合 #517 已選方向。二維平面與側面能先核對位置和指向。重計算約六分鐘，另開行程能讓頁面保有狀態與停止控制。引擎驗證與報表入口共用同一條路，頁面不另定材料或幾何判準。

## 代價

#577 起只有物理身分變了才要重算物理；評分程式或品質登記簿改了，讀回時用存下的物理結果自動重新量或重新排名（同一張紙第九節第 3 條），每打開一份結果頁，存檔後登記簿一格都沒動時多約 0.2 秒，動過任何一格（含多加一個用途）時多約 0.9 秒（14 對實量；那時存下的候選包跟重新量的不再逐字相同，要把身分標籤換成佔位字再比）；比較頁兩份依序讀，是兩份相加（推算）。物理那幾支程式只改註解，或模組、類別、函式開頭的說明字串，不換物理身分（屬性後面的說明字串與欄位的 description 照收）。舊格式 v2、v3 一律重算一次，不轉換、不從提交歷史回推。
品質登記簿變更不再拒收結果（#577）。結果檔保留方案快照，被拒時用當前引擎重算，結果頁提供重算按鈕。第一步沒有頻段進度，只有已跑秒數；分頻多行程另題。畫面考卷讓雲端 verify 每一跑多裝一次無頭瀏覽器；多花的時間在第一次上線時實測，超過一分鐘就改成另開一個同時跑的工作。
