# 第一版介面先做本機網頁與二維圖

## 問題

#516 要把房間方案變成能操作的入口。需決定跑在哪裡、先畫到哪一層，以及輸入、存檔、計算各由誰負責。
四塊範圍「房間與擺位輸入、按鈕計算、聲學結果、方案比較與保存」是覆核者文字；老闆回「大致覺得可以」，不是逐條拍板。

## 選項

1. A：這台電腦跑小伺服器，用瀏覽器開本機網頁；第一版只有老闆自己用。
2. 二維圖先畫平面圖與側面圖；三維圖和網格另排。

## 決定

採本機網頁與二維圖。介面只收輸入、下指令、顯示；計算與評分一律走引擎。JavaScript（網頁腳本）只畫伺服器給的 JSON（資料物件），不寫聲學公式、分數或基準線。這是「介面不准再寫公式、分數或基準線」今天唯一的防線。

伺服器預設只聽 127.0.0.1。要從自己其他裝置直接連，啟動時用 `--listen` 改聽這台的 Tailscale（私人網路）位址：只收 127.0.0.1 或 Tailscale 的 100.64.0.0/10，不收 0.0.0.0 與區網位址；再用 `--allowed-host` 列出瀏覽器會帶的名字（機器短名、全名、位址），127.0.0.1 與 localhost 之外沒列的一律拒收，萬用字元與埠號不收。瀏覽器打機器名加埠號就能開，不用任何管理員指令。

聽在 Tailscale 位址本身擋不住區網與容器：Linux 會把任何網卡收到、寄給本機任一位址的封包照收，2026-09-28 查時這台的防火牆也沒開（ufw 設定 ENABLED=no）。所以聽 Tailscale 位址時，伺服器另外只接受本機與 Tailscale 網段來的連線（扣掉 Tailscale 不發、自己也不擋的 100.115.92.0/23），其他來源回 403，也不信任轉發標頭。這一道擋得住收不到回覆的偽造者；區網裡冒充 100.x 來源的連線，還要靠 Tailscale 自己的防火牆規則（要 root 才看得到，未驗）。2026-09-28 從老闆的另一台 Tailscale 裝置實測連得上。畫面仍照電腦螢幕排，手機版面不在這一版。

方案檔與結果檔存在 repo（程式庫）外；伺服器啟動時拒絕 repo 內的資料路徑。`engine_commit`（引擎提交識別）由啟動的人給完整四十位，不自填佔位值，供結果比較判定是否同版。計算另開行程與行程組，停止時終止整組。第一步只顯示已跑秒數、參考約六分鐘、錯誤原因及結果檔路徑；結果頁在第二步。

表單提供房間長寬高、六面正實數阻抗、選填散射、喇叭與座位座標、主位 z 座標和兩種既有聲源模型；周圍點要逐點改。`feature_match_tolerance_hz`（特徵配對容差）沿用範例考卷的 10 Hz，未查證為產品預設。聲速與密度由範例方案預填。

本步沒提供 `reflection_order_k`（反射階數；只有預設 K=3 有數值考卷）、`low_frequency_axis`（低頻頻率軸；驗證軸耗時未量）、三維圖、拖曳即時重算、帳號，也不做結果頁。

第二步加上結果頁。頻響、各類代價、警戒、逐帶殘響、反射和聆聽區只顯示引擎已算出的資料；
聆聽區逐點差值直接走評估器同一段配對與距離程式。結果檔讀回重評被拒收時，畫面給原因與重算按鈕，
重算從結果檔的方案快照另存一份交給現行引擎，與現在的存檔方案無關。聆聽區按方案實際周圍點距離顯示最遠值；其他座位沒有納入，不作品質暗示。

畫面檢查分兩層。第一層是雲端的畫面考卷：用無頭 Chromium（Chrome 的核心、不開視窗）開本機網頁，驗事先想得到的壞法——每一頁打得開、瀏覽器沒報錯、圖上真的有線、點了有反應、沒有未格式化的數字或空值字樣；瀏覽器在 verify 考卷前那一步安裝，缺了就紅、不跳過。
第二層是每次改畫面都在本機截圖、由人親眼看，抓事先想不到的（字擠在一起、難看、顏色分不清），截圖存在工作資料夾當證據。第一層只能擋已知的形狀；新形狀第一次靠第二層抓到，之後寫進第一層。

## 為什麼

本機單人使用符合 #517 已選方向。二維平面與側面能先核對位置和指向。重計算約六分鐘，另開行程能讓頁面保有狀態與停止控制。引擎驗證與報表入口共用同一條路，頁面不另定材料或幾何判準。

## 代價

結果檔在引擎換版或品質登記簿變更時可能被拒收。結果檔保留方案快照，被拒時用當前引擎重算。第二步結果頁提供重算按鈕。第一步沒有頻段進度，只有已跑秒數；分頻多行程另題。畫面考卷讓雲端 verify 每一跑多裝一次無頭瀏覽器；多花的時間在第一次上線時實測，超過一分鐘就改成另開一個同時跑的工作。
