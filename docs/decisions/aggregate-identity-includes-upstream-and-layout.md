# 彙總類的比較身分要含上游量法與接收點的相對佈局

## 問題

排名層分表只讀每一類對外的兩樣東西：評估器版本與設定指紋。聆聽區那一類的設定指紋只雜湊它自己的一個設定；上游音色的設定指紋、上游評估器版本、接收點清單指紋只住在內層資料裡。批內會查每一點一致，但兩批各自一致、彼此量法不同時，對外的身分一模一樣，會被排在同一張表（2026-09-21 外部審查第 2 條，票 #393）。

## 選項

1. **全部算進對外身分、接收點鎖相對佈局。** 上游設定指紋、上游評估器版本、接收點清單的相對佈局都進對外的設定指紋；相對佈局＝每一點的角色、重要性、相對主位方向、相對主位的位移，不含主位的絕對座標。
2. **全部算進對外身分、接收點鎖絕對座標。** 同上，但直接用現有的接收點清單指紋（含絕對座標）。
3. **排名層自己進內層資料去比。** 對外身分不動，排名層認得每一類的內層欄位。

## 決定

採 1。

- 疊在別的評估上面的類（現在是聆聽區與聲道匹配），對外的設定指紋由四樣組成：自己的設定、每一個上游的設定指紋、每一個上游的評估器版本、接收點清單的相對佈局指紋。
- 批內上游評估器版本不一致，跟設定指紋不一致同樣待遇：不可彙總，原因指名是版本。
- 接收點清單多一個「相對佈局指紋」：每一點的代號、角色、重要性、相對主位方向、相對主位的位移。位移先四捨五入到一個寫在程式裡、有名字的固定小數位再雜湊，免得同一個佈局因為浮點尾數變成兩個身分。原本含絕對座標的指紋照舊留著，用途是批內核對「這些點是不是同一份清單算的」。
- 排名層不改：它照舊只讀對外身分。

## 為什麼

排名層只認對外身分是對的——它不該認得每一類的內層長相，所以洞要在產生身分的那一側補。鎖絕對座標的話，之後位置最佳化每搬一次主位，每個候選就各自一張表，排名失去意義；要比的是「用同一種佈局去量」，不是「在同一個座標量」。

## 代價

- 這一版之前產生的聆聽區與聲道匹配評估，設定指紋全部會變，跟新的排不進同一張表；現在沒有落地保存的舊評估，實際影響是零。
- 位移四捨五入的位數是程式裡的常數，不是品質門檻，不住品質登記簿；改它等於改身分，要走合併請求。
- 之後新增任何疊在別的評估上面的類，都要照這一張組對外身分；沒有機器會自動提醒，靠這張紙與考卷的樣板。
