# 音色要的資料是「計分範圍加平滑半窗」，不齊或有缺段就是不可估

## 問題

音色評估器抓得到頻率軸中間的洞，但原本只掛「覆蓋不足」的旗標就繼續量：把有深谷的那一段頻率整段拿掉，量出來零傾斜零起伏、零代價進榜（2026-09-21 外部審查第 3 條，票 #394）。前一張紙因此規定計分範圍裡缺段就不可估。

同一天的局外終審找到鄰近的變形（R3，票 #409，主線上實跑）：評估器是先對整條曲線做平滑、之後才切出計分範圍，所以計分範圍外側半個平滑視窗的資料也會影響分數。一條只有 4000–4500 Hz 高 15 dB 的曲線，傾斜 0.284387 dB/oct、起伏 1.137832 dB；只把 4000 Hz 以上的點刪掉（計分範圍裡一點都沒少），兩個數都變成 0，照樣已量、過得了缺段檢查。兩個候選手上的資料範圍不同，其實是用兩把不同的尺在量。

## 選項

1. **A：要求資料齊到依賴範圍。** 每個量真正讀到的範圍＝計分範圍往兩側各加半個平滑視窗；資料沒蓋滿或裡面有缺段就不可估。現有算法與數字不動。
2. **B：改算法，平滑只准用計分範圍裡的點。** 不需要外側資料，但邊界附近的平滑值只剩半邊、會偏，現有每一個音色數字與凍結的考卷數字都要重訂。

前一張紙在「缺段怎麼辦」上的三個選項（缺段就不可估／照量但把覆蓋情形算進比較身分／缺段補懲罰值）結論不變：缺段就不可估。

## 決定

採 A，並把前一張紙的規則搬到新的範圍上。

- **依賴範圍由登記簿現算，不寫死。** 傾斜那一個量：傾斜擬合範圍往兩側各加半個「傾斜用的平滑寬度」；起伏（峰谷保護也在這裡找）：起伏範圍往兩側各加半個「起伏用的平滑寬度」。評估器平滑視窗原本就有的捨入護欄照算進去。照今天的登記簿（暫定值）是大約 71–4490 Hz 與 38–4238 Hz。
- **缺段沿用現有判準**：相鄰兩點的距離（八度）大於兩個平滑寬度裡較窄的那一個。不另立新數字。（這個判準比平滑半窗寬一倍的問題記在票 #401，跟平滑寬度那一題一起拍。）
- **資料要完整包住兩個依賴範圍**：第一點不高於下邊界、最後一點不低於上邊界，差一點都不行——邊界上的平滑視窗要讀到那裡。包住之後，兩個依賴範圍各自再判一次缺段，範圍的上下邊界各當成一個虛擬的點。
- **缺段時回不可估**，原因代碼指名「計分依賴範圍內缺段」，跟「點數不夠」分開。音色是必評類，所以那個候選列成「未評估」、不進榜；量得到的部分不回半套。
- **能力宣告算不算驗過用同一個範圍**：報表宣告的頻率範圍要把兩個依賴範圍各自完整包住，狀態又是驗過，才不掛「未驗證」。
- 資料蓋不滿更寬的診斷覆蓋範圍（20–8000 Hz）、但兩個依賴範圍都完整時，照舊只掛「覆蓋不足」旗標、照常量。

## 為什麼

洞的本質是「少交資料反而得利」，A 直接規定少交就不算，跟音色缺段、殘響缺帶、聲道匹配缺點是同一個原則；而且不動算法，現有的分數、考卷、已經拍的數字都不受影響。B 是為了堵洞去改量法：邊界的平滑值變得比較不準，還要重訂一批數字。

範圍現算而不寫死，是因為計分範圍今天只是暫定值（到 4000 Hz）。老闆 2026-09-18 拍過音色評估範圍的目標是 20–8000 Hz（票 #345、#347）；之後計分範圍拉上去，依賴範圍會自己跟著變成到約 9000 Hz，程式不用改。

## 代價

- 計分範圍要拉到 8000 Hz 之前，物理那一側的頻率軸得先拉到約 9000 Hz（票 #347，不是 8000）；順序反了，全部報表的音色都會變成不可估。這件事由一題考卷守：正式登記簿算出來的依賴範圍必須落在正式頻率軸裡。
- 頻率上限今天住三個地方（品質登記簿、頻率軸、能力表），另有一批考卷把數字寫死。能力表上手抄的頻率上限由一題考卷對著頻率軸的最後一點守；登記簿與頻率軸各自仍是一個地方一個數。
- 物理報表若某一段頻率算不出來，整個候選會因為音色不可估而不進榜，不會降級成「先比其他類」。
- 判準綁著平滑寬度：之後拍平滑寬度（#339 清單第 3 題）時，依賴範圍與缺段的門檻都會跟著動，那一題要一併看這個後果。
