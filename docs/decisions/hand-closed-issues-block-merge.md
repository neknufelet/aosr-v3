# 人手關的票超過零張就擋合併，立卡 issues-closed-only-by-merged-pr，第二個准上網的例外

## 問題

票（issue，GitHub 上的待辦票）只准由合進主線的 PR（合併請求）關掉，這件事今天有兩層在守：
守衛 `governance/status/issue_guard.py` 掛在票被關的事件上，人手關的當場重開並留一句人話；
狀態頁上「關掉的票對不對得到綠收據」那一格，把串不起來的列成紅字給人看。
兩層都不擋合併。守衛靠 GitHub 的事件叫起來——事件漏送、或那一跑自己壞掉，票就停在關掉的狀態；
狀態頁是事後給人看的一句話，沒有人看的時候它只是一頁。規矩本身在 `verify`
（GitHub Actions 上那個檢查工作）眼裡不存在：二十六張卡沒有一張在判「人手關的票有幾張」。

## 選項

1. 維持兩層：守衛當場重開、狀態頁紅字。不另立卡。
2. 升成擋合併的規矩卡：檢查上網讀 GitHub 自己記的關票來源，每一張關掉的票都要有一個合進主線的
   關票 PR，沒有的算人手關的，超過零張就回 1。這會是第二支准上網的檢查。
3. 不上網，改判版控裡的憑證：要求每張票關掉時在版控裡留一份「哪個 PR 關了它」的檔。
   那份檔是手寫的，會漂，而且「該留沒留」機器判不出來。

## 決定

選項 2。老闆 2026-09-10 拍板。

具體：
- 新卡 `governance/rules/issues-closed-only-by-merged-pr.toml`，`declared_level = "blocking"`，
  掛在 `verify` 這個 job 上。判準讀 GitHub 自己記的關票來源（PR 內文寫 `Closes #n`，合併時
  GitHub 自己關票並記下那條連結），不看票面上的「互相提到」——提到不等於做掉。
- **這是第二個准上網的例外。** 第一個是 `merge-gate-read-back`（決策紙
  `docs/decisions/merge-gate-check-may-read-github.md`，那張紙寫「只放行這一支」）。
  今天在那張紙的「決定」段補一句指到這裡，不用 `supersedes` 把它標成失效：那張紙講的是
  合併門口的 ruleset 怎麼回讀，整段還在生效，變的只有「例外從一個變成兩個」。
- 放行登記在新卡的 `[[settings.allow]]`，帶 `reason` 與 `expires`，由規矩卡
  `exemptions-need-expiry` 守。到期日 **2026-12-08**，跟第一批放行同一天：一個審查日一次看完。
- 放行有牙：檢查程式自己讀那一筆放行，缺席或過期就回 2、不上網。
- 只准讀。只打兩件事：關掉的票、每一張掛著關它的那幾個 PR。token 用 CI 自帶的那一個，
  `verify` 那一份 workflow 的權限從 `contents: read` 多一格 `issues: read`——那個區塊寫了任何
  一格，沒寫到的每一格就被設成 `none`，所以要讀的那一格得明寫出來。寫回 GitHub 的權限
  （重開票）不在那裡，那是守衛自己那一份 workflow 的事。
- 判準不抄第二份：欄位名、要讀哪幾格、以及「這個 PR 算不算落地」那一支判斷，
  跟狀態頁那一格與守衛共用 `governance/status/collect.py` 裡的同一份。這張卡只換一樣東西
  ——主線分支名從卡上的 `[settings]` 來，不是模組常數，樣本樹才改得動它。
- 某幾張票要具名放過，就在同一張表寫一筆帶票號的放行，一樣要理由與到期日；過期的當沒放行。

## 為什麼

三層各守各的一段，缺一層就有一條路走得過去：

1. **守衛當場重開**（`governance/status/issue_guard.py`）。票一被關就跑，沒有合進主線的關票 PR
   就重開加留言。它最快，但它靠事件，而事件會漏。
2. **這張卡擋合併**。守衛漏了、或有人在守衛壞掉的那段時間關了票，這一層在合併門口咬住：
   人手關的超過零張，`verify` 就是紅的，主線合不進去。它慢一步，但它不靠事件，每一跑都重數一次。
3. **狀態頁紅字**。給人看的那一層，管的是更長的一條鏈（關掉的票對不對得到一份綠的雲端收據），
   不擋合併。它不是前兩層的替身，它問的是另一個問題。

選項 3 抓不到的正是事故的形狀：上一代出過的事是「票關了、東西沒真的落地」，而「該留憑證沒留」
本身就是那個病的一部分——靠人記得留一份手寫憑證，等於再賭一次同一個習慣。
一張票是被誰關掉的這件事只住在 GitHub 上，不上網讀就守不到。

## 代價

- 每一跑上網。這支檢查與它的後設測試六回合從此依賴網路與 GitHub 的 token：本機斷網跑
  `uv run pytest`，第一回合會紅（檢查回 2，第一回合要 0）。雲端那一跑才算數，本機本來就只是宣稱，
  但要知道這是刻意的。
- 准上網的檢查從一支變成兩支。「只放行這一支」那句話今天起不成立了；壓住它的是每一筆放行都
  具名登記在卡上、都有到期日、而且到期那天檢查自己就拒絕上網。第三支要不要放行，是下一張紙的事。
- 歷史上人手關的票要先全部重開、再由 PR 關掉，這張卡才會綠。立卡當天實跑了一次：主線上關掉的票
  二十二張，每一張都對得到一個合進主線的關票 PR，人手關的零張——這張卡在今天的主線上是綠的
  （守衛那一層 2026-09-10 上線之後把先前人手關的都重開過了）。要是雲端第一跑列出了幾張，
  下一步就是把那幾張重開、由 PR 關掉，不是把它們寫進放行。
- 一頁看不完的形狀回 2。一張票掛著上百個關它的 PR 是沒看過的形狀，看不完就不出結論——
  這是刻意選的：猜一個「大概沒有落地的」比說「我沒看完」更糟。
- 每加一張關掉的票，這支檢查就多一筆要問的東西。今天一句圖查詢一頁抓得完；票長到翻好幾頁的時候，
  那一步會變慢，但不會變得不準（翻到底這件事由程式保證，不靠一頁抓幾筆那個數字夠大）。
