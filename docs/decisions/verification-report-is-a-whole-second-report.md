# 驗證報表是另一份完整報表：300 Hz 以下每 1 Hz，只給最後入選的候選

## 問題

正式細軸每八度 24 點，在沒處理的房間最多把 13 dB 的峰頂少量掉（#307），有三根 +10～12 dB 的窄峰整根看不到（#444）。
全部候選都用密軸算太久；只在粗軸看到峰的地方加密，又會漏掉剛好落在兩點中間、粗軸看起來沒峰的那根。
要一套「多數候選用粗軸找、少數候選用密軸確認」的兩階段算法，而且兩份結果的來源要追得到。

## 選項

1. 驗證軸：每 0.5 Hz（561 點，最窄的峰最多少量約 0.7 dB）或每 1 Hz（281 點，最多少量約 2.8 dB）。
2. 驗證結果怎麼進報表：把搜尋報表 300 Hz 以下那一段換成密軸（拼接），或另算一份完整的驗證報表。
3. 誰進驗證：只驗前 N 名，或前 N 名加上淘汰線兩側、細算可能改判的候選。

## 決定

1. **驗證軸**：20–300 Hz（有限元素那一段，含兩端）每 1 Hz 一點；300 Hz 以上照正式細軸。整段照同一個間距掃，不看搜尋軸找到了什麼。
2. **驗證報表是另一份完整報表**：同一個場景用驗證軸從頭算一次，有限元素路與幾何路都在同一條報表軸上算、照常接合；不把搜尋報表的任何一段換掉。兩份各自保存。
3. **報表註明用哪條軸**，而且軸的身分進場景指紋：同一個候選裡，搜尋報表與驗證報表算出的評估不會被當成同一個場景。
4. **頻帶摘要裡取報表逐點的欄位改每八度等權**（有限元素、晚期、交接權重那幾欄；帶內每點乘它代表的八度寬度，格子切到帶的上下緣）：
   報表七帶是 125～8000 Hz，驗證軸在 125、250 Hz 兩帶的點多很多，逐點平均會讓帶內的低段多拿票。搜尋報表也照同一條算，正式細軸在帶內近乎等寬，只差在帶的兩緣。
   0.5 Hz 密軸那幾欄（直達、反射、干涉、散射）兩種報表是同一條密軸，照舊逐點平均。
5. **殘響時間（T20／T30）不跟著換軸**：兩份報表都在正式細軸上算。它是房間的量，不是頻響曲線的解析度，殘響評分因此不受驗證軸影響。
6. **驗證軸只給最後入選的候選**，不准拿去跑大量搜尋。誰算最後入選：同一張可比較榜單的前五名（N＝5，第一版設定），
   加上淘汰線兩側「細算可能改變判定」的候選（剛好過線與剛好沒過線都算）；已有其他確定不合格、細算也不會改變的原因的，不為近線項目再驗。
7. **多近算近用實測訂**：用現有幾組材料、不同聆聽位置，量每一條淘汰指標在兩條軸之間移動多少，寫成「在目前測過的案例裡最多移動多少」，不是保證；量出來前標待定，不准填零。
8. **總計算預算另設**：先列完整待驗名單，再按預算執行；超出預算的標「尚未驗證」，不准宣稱整批驗完；前五名驗完都不合格再從後面補入，沒驗過的不准當最終推薦。
   預算要先在這台機器上實跑一個完整候選的驗證再訂。
9. **呈現**：搜尋名次保留；驗證名次只在已完成驗證、比較條件相同的候選之間重排，寫成「搜尋排名第 1；在已完成驗證的 8 個方案中，排名第 3。另有 2 個方案尚未驗證。」
   驗證完成但峰谷警戒還在，照樣顯示尚待確認。

第 1～5 條在第一刀（報表能換軸）落地。第 6～8 條的挑人在第二刀落地（`src/aosr/scoring/verification_selection.py`）：
第 7 條的範圍照老闆 2026-09-23 拍的 B，是登記簿裡十條「目前測過的案例裡最大換軸差」（原始值）乘倍數 2；範圍為 0 的線（直達聲時間差，只看距離與聲速）不算近線；
範圍外抽查的數量與總預算還沒拍，名單上寫「待定」、不當成 0；名單記下這一輪用的每一個數字、出處與登記簿指紋。
第 9 條的重排與呈現、以及「前五名驗完都不合格再往後補」，留給下一刀。

## 為什麼

- 低頻房間共振峰的寬度由殘響時間決定、是固定幾 Hz（Skålevik 2011："Half-power bandwith B depends only on reverberation time … B = 2.2/T"），
  等 Hz 間距比等八度間距省點數：每八度 192 點（604 點）最多少量 1.2 dB，還不如每 0.5 Hz（561 點）的 0.7 dB（#435 留言的量測表）。
- 拼接出來的曲線來源難追；兩份各自完整，才能清楚說「搜尋第 1，驗證後仍第 1」或「驗證後發現尖峰、重新計分後變第 3」。
- 「增加取樣密度是增加解析度，不是增加那一段的權重」（#446 的原則）；頻帶摘要是逐點平均，不改就會違背。

## 代價

- 每 1 Hz 對半功率寬 2 Hz 以下的窄峰，峰頂可能仍少量 2～3 dB；比「沒處理」更響的房間峰更窄、漏得更多。
- 驗證報表的時間還沒實量。舊的「每點 3.2 秒」只是一支喇叭、一個聆聽位置、有限元素那一段（#307 實跑 1121 點 3850 秒），不代表整個候選；不拿它訂預算。
- 今天一份報表只算一支喇叭對一個聆聽位置，有限元素網格每份重建，同一支喇叭換位置又全部重算；這是之後可以省的地方，不在這一刀改。
- 搜尋報表的頻帶摘要因為改每八度等權，在帶的兩緣會有小幅變動。
- 不同候選分別用搜尋軸與驗證軸算的評估能不能同表，要在排名層把軸的身分算進比較身分，留給第 9 條那一刀。2026-09-25 老闆拍把其中「不能默默混比」這一部分提前拆出（#489）：音色與聆聽區的評估支撐列實際用到的完整頻率（聆聽區含每一點上游音色的那一串），支撐不同先分表；反射、殘響、聲道匹配本來就列實際頻率。做法是列實際頻率，不是列軸的名稱。驗證選人、收斂與重排仍照原時程；粗細結果要同表，另以明確的收斂／誤差規則放寬，這一刀不預先放行。

## 拍板

2026-09-23，老闆在對話裡拍（原話記在 #435）：「我選1 Hz,.0.5 實在太久了 並 只作最後入選候選的驗證軸，不得同步套用到大量搜尋。搜尋軸的 24／48 點另題決定。先修 #446，讓取樣密度不改變評分權重，再做兩階段計算；入選候選細算後要重新排名。」
同日第二題：「我選 A，N 先設 5。」「這次的拍板就是：A，N＝5，先作第一版設定。追加驗證要包含淘汰線兩側；追加範圍用實測訂、不能冒充所有房間的誤差保證；總計算預算另設，不能讓追加名單無限開跑。」
兩份報表分開保存、不拼接，是老闆 2026-09-23 在 #435 的方向：「補算結果不要偷偷把搜尋報表的一段換掉……保留兩份：搜尋結果……與驗證結果」。

2026-09-25，老闆在 #489 原話：「A，現在補。#489只補音色與聆聽區的實際頻率支撐及比較資格；不同支撐先分表，不改既有量法、代價、門檻或峰谷診斷。同時更新兩張決策紙，把這一部分從 #435 提前拆出；驗證選人、收斂與重排仍照原時程。完整支撐要沿上游音色傳到聆聽區，不只記主位、頭尾點數或軸名稱。保留同軸同表、分數不變的控制組，以及只帶音色也能阻擋混軸的反例。將來要讓粗細結果同表，另以明確的收斂／誤差規則放寬，不在這一刀預先放行。先把「不能默默混比」守住，不等於現在就要解完「什麼時候可以混比」。」
