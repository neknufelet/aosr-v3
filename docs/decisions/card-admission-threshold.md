# 什麼東西夠格立卡——四條判準與過門檻的程序

## 問題

規矩卡是這個 repo 唯一的產物，但「什麼東西夠格變成一張卡」沒有紙。2026-09-10 一天之內砍了卡、把牙併進別張、
又改寫了一張，靠的是散在不同地方的三條判準加上當場拍板：一條住在 `reset-from-v2-lessons.md` 的一句話裡、
一條住在卡 `rule-card-required-fields` 的檢查程式裡、一條只活在那天幾張砍卡紙的 `summary` 裡。
搬 `src/`（引擎程式碼那棵樹）進來之後會冒出一批新候選，沒有門檻就會長回上一代那種幾百條規則的樣子。

題目是票 #95。**這張紙沒有照抄票上的骨架**：票上的三條是「對得回事故／有牙／在事故當下會不會紅」，
其中第三條是「算不算血債」的判法、併進本紙第一條；票上沒有的「不與現有檢查守同一件對象」
是從 `drop-handoff-replayable-card.md` 的判決歸納出來的。四條的分法以本紙為準。

## 選項

1. 不立紙，靠對話裡的默契與每次拍板。
2. 只寫「要有牙」一條，其餘留給人。
3. 四條判準全部寫成紙，逐條給出機器問得出來的形狀，並把候選怎麼提、誰找碴、暫緩怎麼解除一起寫死。

## 決定

選項 3。**四條判準**，一張候選四條都過才立卡。每一條都有一個機器問得出來的形狀與一件留在卡面或票上的痕跡。

| # | 判準 | 機器怎麼問（1、2 已做；3、4 已做，票 #217，見附錄） | 痕跡在哪 |
|---|---|---|---|
| 1 | 對得回事故 | 卡面 `blood_debt` 與 `related_lessons` 裡每個事故編號，都要在 `v2-audit/lessons.json` 的 66 筆裡解析得到 | 卡面那兩欄 |
| 2 | 有牙 | 四欄必填，而且卡宣告的必紅樣本餵下去要回紅（離開碼 1） | 卡面四欄 ＋ 必紅樣本 ＋ 後設測試第二回合 |
| 3 | 不與現有檢查守同一件對象 | **已做（票 #217）**：那張卡的必紅樣本，餵給現有每一支檢查；只要有任何一支回紅，就代表這顆牙不是新的 | 必紅樣本 ＋ 後設測試 |
| 4 | 對象今天真的存在 | **已做（票 #217）**：那張卡的必紅樣本裡，要出現它要守的那個對象的檔（`src/` 的規矩，樣本裡就要有 `src/` 底下的檔） | 必紅樣本 |

判準 1 分兩半。**機器只管一半**：卡面 `blood_debt` 與 `related_lessons` 裡**寫了的**編號，都要在
`v2-audit/lessons.json` 的 66 筆裡解析得到（那兩欄是空的就沒有東西可驗，「沒有血債」是一個合法的結論）。
另一半是**人**：這條規矩在事故現場重播會不會亮紅燈、以及「這張卡到底有沒有血債」，都是編輯判斷；
**整格不寫的卡機器不會問**，靠立卡 PR 上的人看。判準 3、4 **已做（票 #217）**（見附錄）。

**今天實際新增的牙只有一顆，而且不另立檢查**：事故編號那顆加在既有的卡 `rule-card-required-fields` 上，
連同程序那一節的票號那一格。判準 3、4 那兩顆（餵給現有每一支檢查、樣本裡要出現對象的檔）
**已做（票 #217）**，加在每張卡本來就要跑的「必紅樣本 ＋ 後設測試」上，不新增掃描面。

**程序**

- 候選先在 GitHub issue 登記，**一張候選一張票**，票上寫候選代號、對到哪筆事故、牙是什麼、要守的對象在哪，
  以及四條判準各自過了沒。不另立檔案，待辦走 issue 由 `backlog-in-github-issues.md` 拍過。
- 指揮提、找碴席獨立否決、爭議才上老闆。**找碴席就是五席制度裡「對抗」那一席**（`five-seats.md`），
  每一張候選都要派，而且不能由提的人自己當。
- 過了就以一個 PR 立卡（卡的 TOML、檢查程式、必紅樣本），PR 內文寫 `Closes #n` 關票，照 `handoff.md` 的做法。
- **卡面多一格 `admission_issue`**：寫那張候選票的號碼。**新卡沒填就紅**（「新卡」＝卡名不在下面那份舊卡名單裡）；
  寫了也要是正整數。這一格是程序唯一強制的痕跡；它**不驗那張票存不存在**（那要上網），
  所以一顆亂填的票號要靠人看 PR 認出來。
- **舊卡名單**：卡名在名單裡的不問票號——那些卡在開票制度之前就立了，一個字都不用改。
  **名單是檢查程式裡一份寫死的清單**，只放「今天真的還在 `governance/rules/` 裡的卡」，
  **不從任何資料檔現算**：現算的算法（今天的 `meta.establishment`）會把每一張新卡都算成
  「不在原本 38 張裡」而自動收進名單，等於這一關自己開後門。
  名單裡**不准有幽靈名**：已經被合併、卡片本體不在樹上的名字要刪掉，留著就是給新卡取那個名字繞過票號。
  反過來，**加了新卡不必（也不准）把它的名字併進名單**——新卡照程序填票號就好；
  名單是一份歷史名冊，不是「今天有哪些卡」的清單。
  它的兩個方向各有取捨：**幽靈名**有機器守（一條測試），**有人偷偷把新卡名字併進名單**沒有機器守——
  那要改檢查程式、會走 PR、靠人看到。
  （名單寫在程式而不是卡的 `[settings]`：這一關要跑得進必紅樣本樹，而樣本樹裡宣告這支檢查的是樣本卡，
  名單住卡上的話每一棵樣本樹都會因為「找不到登記這支檢查的卡」而回 2。）

**暫緩的解除條件只有一個**：它等的對象出現在版控裡。沒有冷卻期、沒有「時間到自動重審」。
暫緩就開一張標籤 `deferred-cards` 的票；**一張候選一張票**（今天一張票裝多張候選的舊分組不再用，
因為立卡是一張卡一個 PR，第一張卡的 PR 一合併就會把整組票關掉，後面還沒動的候選跟著消失）。

**範圍**：這道門檻只管規矩卡（`governance/rules/`）。入口檔的手寫段（`handoff.md` 第一節、`DIRECTION.md`、
`CLAUDE.md` 標記外那幾段）今天**不受**這四條管。

**舊卡怎麼處理**：這張紙不回頭重判已立的 27 張卡。唯一的例外是那兩顆新牙運作所必需的最小資料，
跟牙同一個 PR 一起進，不然樹會紅著進不了主線（今天需要的是：樣本樹自帶一份小號 `v2-audit/lessons.json`）。
紙上不准寫一個做不到的承諾——把新牙限定成「只咬新卡、不咬舊卡」，檢查是對整棵樹跑的，
做不到；要讓舊卡暫時不算，得走 `[[settings.allow]]` 那種帶理由與到期日的具名放行，
**這是選擇不做，不是做不到**。

## 為什麼

- **第一條不是新發明。** `reset-from-v2-lessons.md` 2026-09-09 就拍了「每一張規矩卡都要對回
  `v2-audit/lessons.json` 的某筆事故，或者明白標示沒有 v2 血債」。這張紙把它與另外三條收在一處，
  並且**當場發現它今天沒有牙**：`loader.py` 把 `blood_debt` 列在選填欄位（`:85`），缺欄位就當空值（`:729`），
  27 支檢查裡 `blood_debt` 出現 **0 次**。卡面填一串編出來的事故編號，loader 收下、全部檢查照樣綠——
  那是事故 `verifier-trusts-self-reported-fields`（驗證器信自報欄位、不從原始檔重算）的形狀，
  實例是本 repo 自己的一次稽核（`DIRECTION.md`：合併那步自稱引用 59 個教訓編號，回原始檔對過真的只有 24 個）。
  門檻若建在一個編得出來的欄位上，這張紙就違反它自己。今天那兩欄的幽靈編號是 **0 筆**
  （我用腳本對過 52 筆引用），所以這顆牙加上去不會讓任何一張現有卡變紅。
- **判準 3、4 是老闆一句話改的**（「用人應該會出問題不理想」）——**改的是決定，實作已做（票 #217）**。我原本的兩個寫法都被實測推翻：
  第一版要機器列「兩張卡共同掃到的路徑」，實測 `governance/rules` 被 14 張共用、`**/*.py` 被 5 張共用，
  清單會長到沒人看；第二版要機器驗「`scope` 路徑在版控裡存在」，實測會讓 3 張現有卡當場變紅
  （`ci-jobs-cannot-die-quietly` 的 `scripts`、`green-must-be-real-green` 的 `governance/receipts`
  與幾個對手設定檔、`uv-single-entrypoint` 的 `Makefile`），而且 `scan-scope-has-no-holes` 的卡面
  早就明文拍板相反的事（「宣告了一個今天還沒有檔案的前綴不算違規」）。
  中間試過一個便宜的版本——只比對「樣本檔有沒有被別張卡的掃描面字串搆到」——實測 820 個樣本檔
  **全部**被搆到（有幾張卡宣告 `**/*.py`），鑑別力 0，所以只能真的跑程式。
  成本量過：一棵樣本樹餵全部 27 支檢查要 1.2 秒，新候選准入大約 **16 秒**（不回頭掃舊卡；那要 4 分鐘）。
  判準 4 的機器版選「樣本裡要出現那個對象的檔」，因為它問的正是判準本身，而不是路徑字串存不存在。
- **找碴席不另立角色。** 五席制度裡本來就有「對抗」那一席（`five-seats.md`），本紙用它，
  可以省掉一個沒定義的帽子。
- **不另立新檢查。** 事故編號那顆加在卡 `rule-card-required-fields`，是為了不讓兩支檢查掃同一批檔
  （事故 `guard-teeth-shadow-each-other`，以及 `drop-handoff-replayable-card.md` 拍的
  「沒有新牙的卡不立」）。「反引號包起來的連字號代號必須解析得到」那條**計畫**加在既有的
  `identity-strings-generated` 上——它本來就在守 commit sha 與雲端 run id 要解析得到，
  這次只是把「事故編號、規矩卡名、藍圖候選名」加進同一份清單。
  **那條還沒做**（附錄列為待辦）；做之前量到「今天全樹 38 個這種代號、誤咬 0 個」是**未驗，推測**，
  不能當成已完成的事實。

## 代價

- 判準 1 的「重播會不會紅」與「找碴席有沒有偷懶」都看不出來，只能靠卡面證據與 PR 審。
- **判準 1 的「沒有血債」那一半沒有牙**：`blood_debt` 整格不寫（或空清單）機器不會問，
  所以卡面上看不出它是「查過、真的沒有」還是「根本沒查」。上一版的草稿有一格
  `blood_debt_none_why` 在守這半邊，2026-09-11 拿掉了——理由是老闆拍板「沒有一定要有血債」
  （專案還在進行，後面會有衍生的規則），而那一格的代價是**樣本樹裡的樣本卡也要跟著改**
  （上一版就是這樣逼出一批假卡、把樣本弄髒）。這是**選擇不做，不是做不到**。
- **名單的洩漏方向靠人看**：有人要把一張新卡的名字偷偷併進 `LEGACY_CARD_NAMES`，機器擋不住
  （那要改檢查程式）；能擋的是「幽靈名不准留」那一條，以及改程式會走 PR、會被看到。
- 判準 3、4 的機器版**已做（票 #217）**（見附錄）。每個新候選會多花約 16 秒；代號解析那條要逐條掃規矩卡，
  各檔的總量今天還小，以後卡多了會更慢——`blueprint/cards-38.json` 是 200 KB 的生成物，掃它慢多少**未驗，推測**。
- **牙一的原始檔不是不可變的**：`v2-audit/lessons.json` 沒有雜湊、沒有凍結，同一支 PR 可以編一筆假事故進那份檔、
  再讓卡引用它，機器會放行。機器只保證「你引用的編號在原始檔裡存在」，不保證那筆事故是真的；
  要壓住它得靠 PR 審，或以後替那份檔加雜湊（今天沒有）。
- **票號那一格只驗形狀**：整數字串（`"7"`）與整數都收，字串不是整數、0、負數、小數會紅。
  它**不驗那張票是不是真的存在**（那要上網），所以亂填的票號靠人看 PR 認出來。
- 暫緩候選會一直躺在票上，而且票只能由合進主線的 PR 關掉（`issues-closed-only-by-merged-pr`），
  「對象出現了」這件事沒有機器在盯，靠人記得。
- `v2-audit/lessons.json` 的 66 筆事故裡被血債認領的是少數，其餘今天沒有機器守、靠人看 PR，
  這張紙不假裝它們有人守。

## 拍板

老闆，2026-09-10 到 09-11 對話（issue #95），逐題拍板。紙面狀態先寫 `proposed`——
這張紙自己要不要生效是那張票上還沒定案的一項，等它被拍板才改 `accepted`。
