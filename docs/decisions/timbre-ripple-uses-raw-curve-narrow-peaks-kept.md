# 音色的起伏與峰谷看原始曲線：不平滑、窄峰不刪只標記；傾斜照舊 1/3 八度

## 問題

音色評估器原本先把頻率響應平滑再量：傾斜用 1/3 八度、起伏與峰谷用 1/6 八度，峰或谷要寬於 1/6 八度才算數，三個數字都是暫定（#339 數字清單第 3 題，票 #432）。用參考房四組材料的密掃量過（票 #307、#432 的留言）：1/6 八度在沒處理的房間把 11 dB 的低頻峰磨到 6 dB；「太窄不算」那條規則把處理後的房間 9 個低頻峰、沒處理的房間 19 個**全部**排除——低頻共振正是要抓的東西，卻在打分前就被抹掉。

## 選項

1. 三個數字照現在的升成正式（1/3、1/6、1/6）。
2. 起伏的平滑寬度跟耳朵的解析度隨頻率變（1 kHz 以上 1/6，往下漸寬）。
3. 以 300 Hz 為界，低頻改 1/24、低頻軸加密到每八度 48 點。
4. 起伏與峰谷直接看原始曲線；窄峰不刪，只標記；平滑另外算、不取代原始資料；正式的權重與門檻等看過真的候選跑出來的分數再拍。

## 決定

採 4。老闆的話：保留原始資料，低頻找峰谷、查共振以原始資料為主；平滑用來整理與評分，不是提前替我們決定哪些問題不存在；保留多少資訊跟評分給它多大權重是兩件事。

- 登記簿 `src/aosr/config/data/quality_targets.toml` 的 `timbre_balance.smoothing_width_octave_ripple` 與 `timbre_balance.feature_min_width_octave` 都設 0，狀態仍是暫定基線、出處種類是產品選擇，並標明是**工作設定**：正式數字之後可以再選，改一行加一張紙。
- 評估器（`src/aosr/scoring/timbre.py`）：這兩格准填 0、負的紅；傾斜的平滑寬度仍必須為正。起伏那一支的平滑寬度是 0 時，平滑函式直接回原始能量（不走累積和，逐位元等於輸入），殘差就是原始曲線扣掉傾斜擬合線。「資料軸中間有沒有洞」每一段用自己的尺：傾斜那一段用它的平滑半窗（2026-10-27 票 #401 改，原本是整個視窗寬）；起伏那一段不平滑，相鄰兩點的距離比左右鄰近間距的較大者還大 1.5 倍就是洞——少交一個軸點就不可估，原始曲線少交一點不准變成沒有那個峰；軸由疏變密不算洞。
- 峰谷清單：最小寬度是 0，`FEATURE_TOO_NARROW`（太窄）今天不會出現、規則本身留著；新增標記 `FEATURE_NARROWER_THAN_AXIS`（窄於軸解析度）——半深度寬度不到相鄰軸點距離兩倍的峰或谷，照列、照扣分，只提醒峰頂可能沒量準。相鄰指這個峰左右那兩點、取較大的一邊，從輸入的頻率軸現算，不寫死 1/24，軸可以不等距；寬度未知（邊界不完整）的特徵沒有這個標記。
- 傾斜那一項不動：仍對 1/3 八度平滑後的走勢做最小平方擬合。中高頻的細碎起伏因此會全部進起伏均方根，這是刻意的：留多一點，權重再說。
- 2026-10-20 補（#668）：起伏計分範圍 `timbre_balance.ripple_range_hz` 從 40～8000 Hz 改成 20～8000 Hz（下限等於正式頻率軸第一點）；傾斜擬合範圍 `timbre_balance.tilt_fit_range_hz` 維持 80～4000 Hz，其他音色設定都不動。狀態仍是暫定基線（範圍政策）。網頁上看第二階段結果的地方掛第一階段那句理想聲源標示。
- 2026-10-25 補（#558）：起伏計分範圍 `timbre_balance.ripple_range_hz` 從 20～8000 Hz 改成 300～8000 Hz，20～300 Hz 改由第二階段新增的「低頻頻響」那一類用第一階段量法計分（段序紙 `optimization-stages-room-with-positions-then-layout-then-zoned-materials.md` 第二階段那一點）；峰谷清單另用 `timbre_balance.feature_range_hz`，維持 20～8000 Hz；傾斜擬合範圍與兩個平滑寬度不動。左右匹配的起伏差改用自己的 `channel_matching.ripple_range_hz`（20～8000 Hz），算法與音色同一支。
- 2026-10-26 補（#557）：第二階段那句理想聲源標示照留，照老闆原句：「第二階段的結果頁、比較頁與搜尋頁保留原句，維持一行普通文字，不加頁首橫條或額外警示樣式。第一階段照舊。」「目前第二階段排名仍包含 20～300 Hz 的低頻評估，未加入實際喇叭低頻衰減的前提仍成立。音色起伏改從 300 Hz 起算，不構成移除這句的理由。」「這次只確認現有呈現方式，不改評分、不改聲源模型，也不另開刪除提示的合併請求。」
  畫面確認的範圍照實記：搜尋頁主對話 10-26 截圖看過，是跟上下幾行一樣的普通文字、沒有橫條；結果頁、比較頁當時網頁上沒有存好的結果，這次沒截圖，只照程式讀成一行普通文字、沒另外標色（#866 施工時三頁截圖看過，是 10-20 的畫面）。

## 為什麼

候選代表的是一種擺法與材料，低頻共振是它最要緊的差別；打分前就把峰磨平、把窄峰刪掉，等於用一條規則決定「這些問題不存在」。平滑是為了讓人看得出走勢，不是為了打分；而且同一批頻點算出來之後，要幾種平滑版本都能從原始資料再生，不用重算物理。1/24 的最小寬度也不夠（沒處理房間的峰半深度寬只有 1/40–1/150 八度），所以乾脆不刪。

2026-10-20 補（#668）：起伏從 40 Hz 起算時，20～40 Hz 的頻響峰（房間第一個共振常落在這一段）沒有任何一類的代價看得到；改從 20 Hz 起，對齊老闆 2026-09-18 在 #347 拍的音色評估範圍 20～8,000 Hz。傾斜不跟著往下：它管整體偏亮還是偏暗，不該讓房間低音那一包決定。

2026-10-25 補（#558）：20～300 Hz 原本經音色起伏計分（扣 80～4000 Hz 擬出的寬頻傾斜線），老闆要第二階段另用第一階段量法（扣那一段自己的線）計分；兩種量法在房 109、66 方向相反（三間合報，#558 留言 6395030718），兩把都留就是同一段算兩次、而且彼此抵觸。老闆選分開計分，原話「不先合併重複計分版」，低頻那段只交給第一階段量法。

## 代價

- 中高頻的起伏均方根會變大、不同候選之間的差距會被 300 Hz 以上鏡像法算不準的細碎起伏放大；權重那一題（#339 第 8 題）要把這件事算進去。這一段先不改，理由是「1/6 只是拿來看較寬頻的平衡」，不是宣告細節都是雜訊。
- 起伏均方根與峰谷深度的絕對值跟以前的暫定值不可比；已經跑過的成績要重跑。
- 原始曲線本身仍可能沒抓到峰頂：正式軸每八度 24 點，在沒處理的房間最多漏 13 dB 的峰高（#307）。「窄於軸解析度」的標記只是提醒，不補救。低頻軸要不要加密、最後入選的候選要不要在尖峰附近補算，另開票；報表要保留複數聲壓（幅度與相位）也另開票。
- 「窄於軸解析度」的門檻是兩個軸點距離、不平滑時判洞的尺是鄰近間距的 1.5 倍，都是工程上的下限，沒有文獻出處。
- 這一張沒有用真的候選跑過排名比較（老闆決定直接用原始資料、不先比）。
- 2026-10-20 補（#668）：喇叭模型在 40 Hz 以下照樣全力發聲（理想聲源），真實小喇叭這一段小很多，20～40 Hz 進起伏之後可能比實際重，所以第二階段結果也掛「未加入實際喇叭的低頻衰減」那句標示。改了以後，存過的方案讀回時用存下的物理重新量過、重新排名，不重算物理；起伏均方根與排名跟改之前不可比。
- 2026-10-25 補（#558）：起伏均方根改從 300 Hz 起算後，跟 10-20 那一版也不可比；存過的方案讀回時重新量測（舊檔沒有低頻頻響那一類）、重新排名，不重算物理。三間存檔的新舊分項與排名核對在 #558 留言 6401996068。
