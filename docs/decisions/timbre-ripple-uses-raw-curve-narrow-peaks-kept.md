# 音色的起伏與峰谷看原始曲線：不平滑、窄峰不刪只標記；傾斜照舊 1/3 八度

## 問題

音色評估器原本先把頻率響應平滑再量：傾斜用 1/3 八度、起伏與峰谷用 1/6 八度，峰或谷要寬於 1/6 八度才算數，三個數字都是暫定（#339 數字清單第 3 題，票 #432）。用參考房四組材料的密掃量過（票 #307、#432 的留言）：1/6 八度在沒處理的房間把 11 dB 的低頻峰磨到 6 dB；「太窄不算」那條規則把處理後的房間 9 個低頻峰、沒處理的房間 19 個**全部**排除——低頻共振正是要抓的東西，卻在打分前就被抹掉。

## 選項

1. 三個數字照現在的升成正式（1/3、1/6、1/6）。
2. 起伏的平滑寬度跟耳朵的解析度隨頻率變（1 kHz 以上 1/6，往下漸寬）。
3. 以 300 Hz 為界，低頻改 1/24、低頻軸加密到每八度 48 點。
4. 起伏與峰谷直接看原始曲線；窄峰不刪，只標記；平滑另外算、不取代原始資料；正式的權重與門檻等看過真的候選跑出來的分數再拍。

## 決定

採 4。老闆的話：保留原始資料，低頻找峰谷、查共振以原始資料為主；平滑用來整理與評分，不是提前替我們決定哪些問題不存在；保留多少資訊跟評分給它多大權重是兩件事。

- 登記簿 `src/aosr/config/data/quality_targets.toml` 的 `timbre_balance.smoothing_width_octave_ripple` 與 `timbre_balance.feature_min_width_octave` 都設 0，狀態仍是暫定基線、出處種類是產品選擇，並標明是**工作設定**：正式數字之後可以再選，改一行加一張紙。
- 評估器（`src/aosr/scoring/timbre.py`）：這兩格准填 0、負的紅；傾斜的平滑寬度仍必須為正。起伏那一支的平滑寬度是 0 時，平滑視窗只剩那一點，殘差就是原始曲線扣掉傾斜擬合線。「資料軸中間有沒有洞」只拿寬度為正的那幾支判，寬度 0 的那一支沒有視窗可言。
- 峰谷清單：最小寬度是 0，`FEATURE_TOO_NARROW`（太窄）今天不會出現、規則本身留著；新增標記 `FEATURE_NARROWER_THAN_AXIS`（窄於軸解析度）——半深度寬度不到相鄰軸點距離兩倍的峰或谷，照列、照扣分，只提醒峰頂可能沒量準。軸點距離從輸入的頻率軸現算，不寫死 1/24。
- 傾斜那一項不動：仍對 1/3 八度平滑後的走勢做最小平方擬合。中高頻的細碎起伏因此會全部進起伏均方根，這是刻意的：留多一點，權重再說。

## 為什麼

候選代表的是一種擺法與材料，低頻共振是它最要緊的差別；打分前就把峰磨平、把窄峰刪掉，等於用一條規則決定「這些問題不存在」。平滑是為了讓人看得出走勢，不是為了打分；而且同一批頻點算出來之後，要幾種平滑版本都能從原始資料再生，不用重算物理。1/24 的最小寬度也不夠（沒處理房間的峰半深度寬只有 1/40–1/150 八度），所以乾脆不刪。

## 代價

- 中高頻的起伏均方根會變大、不同候選之間的差距會被 300 Hz 以上鏡像法算不準的細碎起伏放大；權重那一題（#339 第 8 題）要把這件事算進去。這一段先不改，理由是「1/6 只是拿來看較寬頻的平衡」，不是宣告細節都是雜訊。
- 起伏均方根與峰谷深度的絕對值跟以前的暫定值不可比；已經跑過的成績要重跑。
- 原始曲線本身仍可能沒抓到峰頂：正式軸每八度 24 點，在沒處理的房間最多漏 13 dB 的峰高（#307）。「窄於軸解析度」的標記只是提醒，不補救。低頻軸要不要加密、最後入選的候選要不要在尖峰附近補算，另開票；報表要保留複數聲壓（幅度與相位）也另開票。
- 「窄於軸解析度」的門檻是兩個軸點距離，這是工程上的下限，沒有文獻出處。
- 這一張沒有用真的候選跑過排名比較（老闆決定直接用原始資料、不先比）。
