# 雲端那一跑是唯一權威，檢查與收據都圍著它走

## 問題

三張舊紙分別回答「誰有裁決權」、「哪裡執行檢查」與「收據由誰產、放哪裡」。它們是同一條權威鏈，拆開後容易只讀到其中一段：本機結果可以留下，但不能裁決；雲端檢查要真的執行；算數的收據還要由那一跑自己打包並留在機器分支。第三張紙處理的是 issue #14。

## 選項

逐張的完整選項在 `docs/archive/` 的舊紙。第一張比較過「所有席位只認雲端」、「只有驗收席必須用雲端」與「雲端是唯一權威、本機只算宣稱」；第二張比較過本機 pre-commit（提交前檢查）為主或雲端 CI（持續整合）為唯一執行者；第三張比較過兩層收據、只留本機派工收據而砍掉三張卡、以及把機器收據寫回主線。

## 決定

**雲端那一跑是唯一權威，本機收據只是宣稱（2026-09-09）。** 採第三個選項。收據的 `authority` 欄只有 `cloud-run` 與 `claim` 兩值，沒有第三種，也沒有「本機但算數」；前者必附 GitHub Actions（GitHub 自動化工作）的 run id（執行編號）供機器回查，後者只是宣稱。指揮不因終審身分重跑所有東西，而是讀雲端裁決；只親自重跑票上具名的高風險斷言。工人可附本機結果供參考，但合併請求能不能合只看雲端，不需替本機結果開豁免。

**只有雲端檢查算數（2026-09-09，拍板在 2026-09-08）。** 採第二個選項。規矩卡的「執行者」只能填 CI job（持續整合工作）名；本機 hook（掛鉤）可以安裝來加速回饋，但不得申報為執行者。測試分兩層：合併必過層不用 GPU（圖形處理器）、不用網路，15 分鐘內跑完且環境封閉；GPU 與長測試層在 `florian-coder` 自架 runner（執行機）上跑，不擋合併，紅了開 issue（待辦票）並在狀態頁印紅字。第二層只由推到 `main` 主線與手動觸發叫起，外部合併請求要人工核准才可在自架執行機上跑。

**收據分兩層，雲端收據住機器分支（2026-09-10，issue #63）。** 採第一個選項。`verify`（驗證工作）每次把每支檢查的離開碼、報告行、pytest 的 junit（測試結果檔）、run id 與所掃的 commit（提交）打包成一跑一份的機器收據；生產者是雲端那一跑，不是任何席位的自報。收據與狀態頁共用 `.github/workflows/status.yml` 的推送流程，住只有機器寫的 `status` 分支，不進主線。本機派工收據留在 repo（版本庫）外，合併請求只貼摘要與雜湊，並標 `authority = "claim"`。

三張收據卡 `four-roles-different-actors`、`receipt-schema-complete`、`receipt-authority-is-the-cloud-run` 的解除條件是：生產者上線，而且 `status` 分支已有第一份機器收據；在那之前維持暫緩。實作要讓合併請求工作樹能抓到 `status` 分支或讀取已抓下來的 ref（參照），並接受卡驗的是先前幾跑的收據，因為當下一跑的收據要等檢查結束後才寫得出來。issue #11 的三張票務候選仍要另判是改成看收據，或由 delivery skill（交付流程工具）的測試守。

## 為什麼

事故 `builder-grades-own-work-edits-ruler`（7 次復發、嚴重度 5）與 `verifier-trusts-self-reported-fields`（9 起收據假綠）都源於被查的一方自己寫裁決。上一代把 pre-commit 寫成執行牙，實際掛鉤空了 3 個月；後來的守衛又有 5 種靜默失效，4 家工具中當時只有 1 家裝得起掛鉤。讓雲端那一跑執行檢查、保存平台紀錄，再由那一跑打包收據，裁決者、被查者與收據作者才不會混在一起。機器產物放 `status` 分支，是因為它不該用自動提交灌滿主線歷史。

## 代價

- 第一張舊紙的代價：雲端跑不到的 GPU、長測試或本機工具沒有權威收據，只能算宣稱；要算數就得搬上雲端或自架執行機。當時收據產生器還不存在，`receipt-authority-is-the-cloud-run` 要等 `receipts-exist`。合併門口設定能否上網回讀另開一題，不在這一族擴張。
- 第二張舊紙的代價：公開版本庫上的自架執行機有外人跑程式的風險，靠核准機制擋；GPU 層不擋合併，紅了要有人看狀態頁。
- 第三張舊紙的代價：生產者要另改 `status.yml`；合併請求樹如何讀 `status` 與「只能驗先前幾跑」都是實作題。本機派工收據永遠只是宣稱，本機四席是否分開與找碴席是否換來源，機器只能從雲端收據反推。issue #11 還要另判。
- 合併帶來的代價：權威、執行位置與收據位置在機器眼裡成為同一題；之後其中一題要翻案，得取代整張並重帶其餘仍有效的決定。
