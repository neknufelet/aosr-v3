# 幾何量的精度契約：跟參考答案逐位元相同

## 問題

決策紙 `engine-grows-by-room-workflow` 規定：寫候選實作之前先訂精度契約，不准看到候選差異才放寬。
票 #175 第一段做完，參考答案有了，要在第二段開工前把「對到哪一位」講死。

## 選項

1. **逐位元相同**：v3 算出的每個浮點數，`float.hex()` 的字串跟答案檔逐字相等。
2. **容許最後幾位差**（例如 4 ULP，ULP 是浮點數最小刻度）：讓不同但同樣正確的寫法過關。

## 決定

採選項 1，範圍只有這一階段的**幾何量**：鏡像座標、路徑距離、到達時間。
- 裁判是 `tests/test_reference_room_answers.py` 的逐位比對（hex 字串相等），答案檔是 `blueprint/reference_room_answers.json`。
- 第二段的 v3 程式算出來的這三個量，也走同一支比對，不另寫一套。
- 等不了的時候（換機器、換函式庫、換寫法算出來不同）：另立一張決策紙說明原因與證據，不准在考卷裡加容差。
- 振幅、材料反應、二階以上反射、外部模擬器交叉驗證：各自另訂契約，不套用這一張。

## 為什麼

- 證據：獨立用標準庫寫同一條公式（平方和開根號），七條路徑跟上一代逐位元相同；換成 `hypot` 那種寫法差 1 ULP。
  也就是說逐位元相同做得到，代價只是「用同一種寫法」，而這幾個量的公式簡單到沒有理由用別的。
- 比對是二選一（等或不等），沒有一個容差數字可以慢慢長大——上一代的教訓正是容差一鬆、幾百題一起假綠。

## 代價

- v3 被綁在同一種算法寫法；想用 `hypot` 或其他次序的加法就會紅。
- 換平台若算出不同位元，要走決策不能走容差；那時候會慢一步。
