# 決定一題一張紙

## 問題

拍板的事記在哪，怎麼跟經驗談、commit、狀態分開，怎麼不放著爛。

## 選項

1. 全放 cairn，照 v2。
2. 只寫在 commit message。
3. 獨立資料夾，一題一檔，固定格式，機器守結構。

## 決定

選項 3。`docs/decisions/<描述性主題>.md`，frontmatter 帶狀態、日期、supersedes、superseded_by；正文五段：問題、選項、決定、為什麼、代價。索引由指令生成。
機器守：同題只有一份 accepted、取代鏈不成環、決策紙引用的路徑必須存在、動到契約／裁判／物理路徑的 PR 必須引用一張決策紙。
cairn 只留經驗（試過什麼沒用、外部硬限制、量錯的坑），可引用決策紙但不得再抄一份決定；cairn 的 LOG 改為從主題檔生成的索引，不再手寫。
落檔責任分三層：指揮當場寫（習慣，會漏）；收工 hook 提醒「有拍板未落檔嗎」；PR 檢查擋（保證）。老闆覺得是決定時說「記下來」。
邊做邊寫，不事先編目錄。

## 為什麼

v2 最大的決定「凍結 v2 開 v3」只在對話與橫幅裡，cairn 零紀錄；LOG 手寫長到 120 KB；裁判錨點同日定兩次三版並列。決策紙寫「某日決定 X」不宣稱現在，不會像狀態檔那樣說謊；被 PR 引用的會持續被翻，沒人引用的放著不花錢。

## 代價

「對話裡拍了板卻沒寫」機器抓不到，只能靠習慣與提醒，最晚在 PR 被擋時補。
