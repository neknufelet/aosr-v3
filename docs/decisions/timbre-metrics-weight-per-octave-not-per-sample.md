# 音色的積分量每八度等權，不讓取樣密度變成票數

## 問題

參考房的 flat（水平）材料只把 300 Hz 以下從正式 1/24 八度軸的 94 點加密到 1121 點，
300 Hz 以上一點都沒動，音色評估器的傾斜卻從 1.052 變成 2.057 dB/oct（每八度分貝），
起伏 RMS（均方根）從 4.77 變成 3.92 dB（分貝）；連資料完全相同的 6450 Hz 與 6834 Hz
兩個谷，深度也從 −14／−16 變成 −20／−22 dB。原因是四處都把每個取樣點當一票：
傾斜的直線擬合、能量域平滑、起伏均方根，以及對目標偏差的扣平均與均方根。

## 選項

1. **A：每點等權。** 維持現狀；哪一段取樣密，哪一段就有更多票。
2. **B：每 Hz（赫茲）等權。** 線性頻率跨度相同就同票，高頻的一八度會比低頻的一八度重很多。
3. **C：每八度等權。** 每點的票數等於它代表的 log2(f)（以二為底的頻率對數）寬度；
   50→100 Hz 與 1000→2000 Hz 都是一八度，基本權重相同。

## 決定

採 C，四處用同一份整軸八度權重：傾斜用加權最小平方，能量域平滑在每個截短視窗內做
加權平均，起伏用加權均方根，對目標偏差的扣平均與均方根也加權。計分範圍只從整條軸
取權重子集，不在範圍邊界重算，免得邊界改變範圍內點原本代表的寬度。

raw（原始）峰谷照 #432 保留：`_features`（峰谷找法）、半深度寬度與窄於軸解析度標記仍看
原始曲線逐點，不為擬合降回粗軸，也不重取樣。加密若真的找到粗軸沒抓到的窄峰，峰谷清單
與起伏均方根本來就應該變。

## 為什麼

老闆的判準是：「增加取樣密度是增加解析度，不是增加那一段的權重」。聲學頻率用比例看，
兩段各一八度的區間基本權重相同；加密只把同一段切成更多小份，不會憑空增加那一段的票數。

## 代價

量法改變後，正式登記簿下的參考房傾斜、起伏與對目標偏差都要重跑，不能沿用舊收據。
2026-09-23 實跑四組材料（腳本與原始輸出在工作區 `446-octave-weights/`）。正式 1/24 等比軸上
每點的八度寬度全等，只有計分範圍兩端的格子被切到範圍邊界（半格），所以改前→改後只差在
第二、三位小數；依序為傾斜（dB/oct）／起伏（dB）／對目標偏差（dB）：

- flat（水平）：1.051766／4.773146／5.117599 → 1.041058／4.774612／5.099118。
- lowabs（低頻吸收）：0.761535／5.321767／5.773256 → 0.758588／5.322886／5.758829。
- treated（處理）：0.217087／6.607392／6.644590 → 0.215360／6.618380／6.647740。
- untreated（未處理）：0.328409／7.645804／7.777094 → 0.322401／7.663318／7.785981。

同一次實跑把 300 Hz 以下換成 0.25 Hz 密掃（1121 點）、其餘不動；下列是「密掃減正式軸」的差，
每點等權（v6）→每八度等權（v7）。取樣密度造成的偏移明顯縮小；仍留下的差是密掃真的找到的
新資訊（treated／untreated 有粗軸漏掉的窄峰），不要求歸零：

- flat（水平）：`+1.004983／−0.856549／−0.532354` → `+0.002134／−0.000531／+0.000570`。
- lowabs（低頻吸收）：`+0.256172／−0.061228／−0.145864` → `−0.008859／+0.005936／−0.000814`。
- treated（處理）：`−0.025786／+2.231531／+1.424865` → `−0.114956／+0.257899／+0.104585`。
- untreated（未處理）：`−0.648728／+3.555468／+1.767660` → `−0.383185／+0.666364／+0.181848`。

當初的症狀——資料完全沒動的 6450／6834 Hz 兩個谷，深度隨低頻加密從 −14／−16 變 −20／−22 dB——
在 v7 下兩種軸都是 −14.04／−16.15 dB，不再跟著動。

- 聲道匹配的頻率差曲線（`channel_matching.py` 呼叫同一支平滑）也跟著改成每八度加權；它的評估器
  版本字串沒升，但比較身分含上游音色版本 v7，新舊評估會分表。寬頻音量差（`_measured_point`
  的能量加總）仍是每點一票，另開票處理，不在這裡擴大範圍。
- 平滑的視窗加總用 Python 迴圈逐窗相加（避開累積和相減把 1e-30 洗成 0）：1247 點約 5～11 毫秒、
  5000 點約 20～47 毫秒一次（兩席各量一次，差在機器負載），可接受；要更快再改向量化。

## 拍板

2026-09-23，老闆在票 #446 原話：「#446 做，先於 #435。明定為『每八度等權』，不是每 Hz
等權；一併修傾斜擬合、能量域平滑、起伏 RMS，以及對目標偏差的扣平均與 RMS。raw 峰谷
保留，不為擬合而降回粗軸。」「考卷要防『多取點就多加權』，但不能禁止『加密發現新缺陷後
答案合理改變』。」白話：「原本是低頻班 94 個學生、高頻班幾十個學生一起投票；現在低頻班
突然變成 1121 個學生，高頻班沒變，那最後投票結果當然被低頻班淹沒。問題不是低頻資訊變
詳細，而是詳細資料被錯當成更多票。」「增加取樣密度是增加解析度，不是增加那一段的權重。」
