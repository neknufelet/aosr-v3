# 文件怎麼放、決策紙怎麼寫、入口檔長什麼樣

## 問題

三張紙各管文件的一面：東西放哪（`docs-four-classes-archive-for-superseded.md`）、決策紙怎麼寫與怎麼往封存區沉（`one-decision-one-paper-may-merge-many.md`）、入口檔從哪裡來與多長（`entry-files-generated-rules-pointer-line-cap.md`）。機器版是同一組卡。2026-10-28 活的決策紙 59 份、上限 60，第三階段要開新紙沒有位置；這三張沒有暫定項、沒有待拍的子題，合成一張空出兩個名額。逐張的完整問題、選項與原始拍板都在 `docs/archive/` 的舊紙；本紙把每一張仍然有效的決定逐條寫進來，不改任何一條。

## 選項

- **A**：三張合成一張，舊紙搬去封存，份數上限 60 不調（照 `one-decision-one-paper-may-merge-many.md` 自己定的合併規則）。
- **B**：上限提到 80。舊紙那一題已經否決過：上限一提就不是上限。

## 決定

採 A。下面三節各對應一張舊紙，決定逐條照搬。

### 一、docs 四類加封存區（原 2026-09-15）

1. `docs/` 四類平行不分層：`decisions/`（活的決定）、`archive/`（被取代的決定）、`design/`（設計文件）、`cairn/`（做過的事沉澱成的可重用知識）。三道柵欄照舊：**限種類**——工人紀錄、審查、進度快照、每票報告一律不進 repo，只活在 issue 與 PR，放錯種類紅；**限數量**——各類各設上限，用 `git ls-files` 數（以版控索引為準，不走檔案系統掃描），超過就紅，逼人先刪再加；**算得出來的不存檔**——能由機器算出來的狀態不手寫進版控。封存區只收決策紙，不收過程紀錄。
2. 標了 `superseded` 的紙必須住 `docs/archive/`；`docs/archive/` 裡只准有標了 `superseded` 的紙；取代關係跨兩層找；兩層同一個檔名即紅。開新紙取代舊紙的那支合併請求就得把舊紙搬走，不搬雲端紅。
3. 封存的紙只搬不改；兩個例外：被取代那一刻本來就要改的 `status` 與 `superseded_by` 兩格，以及紙裡指到別份決策紙的路徑（那份也搬了）要跟著改。
4. `decisions` 上限 60 不動，數的是活的那一層；`archive` 另設上限；總量上限跟著提，仍比各類相加緊。數字住 `doc-frontmatter-and-dates` 卡上，這裡不抄。
5. 檔案白名單卡的 docs 那一層含 `archive`。
6. 讀舊決定去 `docs/archive/`；活的紙的 `supersedes` 欄仍寫舊紙的檔名，不帶目錄。

### 二、決策一題一張紙，一張新紙可以合併取代好幾張舊紙（原 2026-09-09、09-21）

1. 決策放 `docs/decisions/<描述性主題>.md`，一題一檔；標頭帶狀態、日期、取代誰、被誰取代；正文固定段落（問題、選項、決定、為什麼、代價、拍板）；同題只准一份生效、取代鏈不成環；知識區只留經驗，不再抄一份決定；邊做邊寫，不事先編目錄。
2. 動到契約、裁判或物理路徑的合併請求必須引用一張決策紙（這一條還沒有立卡）。落檔責任三層：指揮當場寫（習慣，會漏）、收工時提醒、合併請求的檢查擋；老闆覺得是決定時說「記下來」。
3. 取代誰（`supersedes`）那一格可以列好幾個檔名，同一行用逗號隔開；被誰取代（`superseded_by`）仍然只准一個檔名——一張舊紙只被一張紙接手。雙向都要對得上：新紙列到的每一張舊紙都要指回新紙；舊紙指到的新紙也要把它列在清單裡；清單有空項或同一張列兩次就紅。
4. 新紙一生效，它列到的每一張舊紙就必須標成已被取代，標了就要搬到 `docs/archive/`（第一節第 2 條）。
5. 逗號是清單的分隔字元，決策紙的檔名不准含逗號。
6. 合併出來的新紙要把每一張舊紙仍然有效的決定寫進自己的「決定」段，不能只寫「見舊紙」——舊紙進了封存區就不算數了。
7. 份數上限 60 不調。

### 三、入口原稿只生成規矩節，第二份入口是指路牌，全檔上限 120 行（原 2026-09-09、09-10）

1. 一條規矩一個 TOML（設定檔），放在 `governance/rules/`；必填人話一句、檢查指令、必紅樣本路徑、掃描範圍、離開碼 0／1／2（乾淨／違規／工具自壞）、執行它的 CI job（持續整合工作）名、帶到期日的豁免。湊不出必紅樣本的不是規矩，要放到知識區。
2. `CLAUDE.md` 的規矩節由卡片生成，以標記包住，CI 重生比對，手改即紅；規矩節每張卡只渲染人話第一句，一卡一行。標記外手寫座標、一行驗證指令、狀態與決策入口、七條習慣。歷史往決策紙與知識區沉。
3. `AGENTS.md` 只是指路牌：內容只住 `CLAUDE.md`；`AGENTS.md` 由同一支產生器寫固定幾行，說入口在哪、開工先讀哪裡與一行驗證指令。指路牌文本登記在 `entry-files-rendered-from-registry` 的 `[settings]`，多一字或少一字都紅。
4. 兩份入口檔各自不得超過 120 行；唯一數值來源是那張卡的 `[settings] max_lines`，不得為單次變更過關而調，要改必須另寫決策紙。上限用來逼人留白，不是給人填滿；手寫段與規矩節共用同一空間。按卡數自動長大的上限不採用，因為它不會響。

## 為什麼

- 活的目錄只放還算數的決定，讀的人不用先看狀態欄；收不收靠機器——上一代封存了 715 份還是長回去，因為封存靠人事後盤點；「取代就得搬」做成同一支合併請求的紅綠燈。不把「死的不算」寫進計數規則：檔案混在活的目錄裡正是「有用的被埋掉」的開始。上限一提就不是上限。
- 一換一份數永遠不會少，上限的用意是逼舊事合併下沉，不是到了就加；v2 的病就是文件越堆越多、沒有人讀得完。
- 上一代入口原稿 432 行、九月改 31 次，程式內還有 360 處「禁裸 Any」與 88 處「禁 print」的文字規矩違反；早期 91 行長到 413 行。卡片是單一來源、入口只渲染一句，可避免規則、守衛範圍與程式三邊漂；120 行逼新增內容先做取捨。兩份逐字副本讓「開工先讀哪份」有兩個答案，指路牌只留一個。

## 代價

- 封存區只增不減：刪一份封存紙，接手的活紙 `supersedes` 就指空，結構卡會紅；封存區上限與總量上限遲早撞線，那時另開一題。封存區的紙不被 `no-model-names-in-entry-files` 掃（它只掃 `docs/decisions/`）。
- 「對話裡拍了板卻沒寫」機器抓不到，只能靠習慣與提醒。合併舊紙是人工活，搬漏了機器看不出來；哪幾張算「同一族」機器也不判。被合併的那一群紙在機器眼裡變成「同一題」，之後其中任何一個子題要重決，就得取代整張合併紙。
- 卡繼續增加時規矩節會逼近 120 行，到時只能縮手寫段或另寫紙調上限，不能直接改設定值。不讀原稿的工具只看到指路牌，它必須沿指示讀原稿。
- 合成這一張的代價：規矩卡的檔頭註解、三支檢查程式與產生器的說明、一份活的決策紙與知識紙裡指到舊紙的路徑，都改指本紙或 `docs/archive/`；卡上註解改的是說明文字，不改任何規則與數字。
