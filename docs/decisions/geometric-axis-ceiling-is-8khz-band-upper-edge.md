# 幾何路細軸上限是 8000 Hz 八度帶上緣，與報表帶清單脫鉤

## 問題

音色的診斷與起伏計分範圍已拍到 8000 Hz；音色資料契約又要求計分範圍外加平滑半窗。
原本幾何路共用細軸只到 4000 Hz 八度帶上緣，無法完整承載這個範圍。另一方面，若順手把
8000 Hz 加進報表帶清單，鏡像法的 0.5 Hz 密軸會多出一大段計算成本；那是另一題。

## 選項

1. A：細軸上限拉到 8000 Hz 八度帶上緣，報表帶清單仍到 4000 Hz，兩者脫鉤。
2. B：細軸與報表帶清單一起加到 8000 Hz，現在就承擔新增密軸點的成本。

## 決定

採 A，修正 `stage-nine-reflection-order-is-a-setting.md` 第 6 條的上緣。

- `GEOMETRIC_AXIS_UPPER_HZ`（幾何路細軸上限）是 `8000·√2` Hz，正式 1/24 八度細軸取不超過
  這個上限的最後一點。
- `GEOMETRIC_REPORT_OCTAVE_CENTERS_HZ`（幾何報表八度帶中心清單）仍是 125、250、500、
  1000、2000、4000 Hz；細軸上限不再由最後一個報表帶反推。
- `timbre_balance.ripple_range_hz`（音色起伏計分範圍）上緣改為 8000 Hz。起伏平滑寬度是零，
  所以不另加半窗；傾斜的 1/3 八度平滑半窗則仍完整落在新細軸內。
- `timbre_balance.tilt_fit_range_hz`（音色傾斜擬合範圍）維持 80–4000 Hz；本題不重訂由這段
  範圍推導的正式容許帶。
- 有限元素路的 300 Hz 上限與全部有限元素頻點不變。
- 能力表 `src/aosr/config/data/capabilities.toml` 宣告整條細軸的五列（三路報表三種材料形式、型錄反推、
  音色評估器）`frequency_hz` 上限由 5583 改成 11166（細軸最後一點取整）；`late_energy` 那列是逐帶的入口，
  仍寫 125–4000。
- 評估器邊界修正：`src/aosr/scoring/timbre.py` 的半窗在平滑寬度 0 時回 0——不平滑沒有視窗、也就沒有
  捨入護欄；否則依賴上界比計分上界高一根頭髮，資料剛好量到 8000.0 Hz 的曲線會被判「計分範圍有缺」。

## 為什麼

老闆已拍音色評估到 8000 Hz。把幾何路細軸拉到該八度帶上緣，可以同時包住 8000 Hz 計分
範圍與傾斜平滑所需的外側半窗。報表帶清單保持不動，則不會在還沒報成本、另行拍板以前，
讓鏡像法的 0.5 Hz 密軸跟著擴張。

## 代價

- 幾何路逐點計算多 24 點（196→220）；有限元素路與報表密軸點數不變。新增的 24 點落在 5657 Hz 以上、
  不進任何一個報表八度帶，所以六帶的帶內平均、交接權重、逐帶殘響全部逐位不變；吃到新高頻的是走
  報表逐點表進音色評估器的那一路。
- 對外看得到的兩個變化：正式報表的音色不再掛「覆蓋不足」旗標（細軸已蓋滿 20–8000 Hz 的診斷範圍）；
  殘響 4000 Hz 帶的模型驗證狀態從「沒查過」變成照抄能力表的「試驗中」（能力表上限 11166 已包住該帶上緣
  5657，之前的 5583 沒包住）。
- 8000 Hz 報表帶與殘響目標這次仍未啟用；是否增加該帶要另題先報密軸成本。
- 型錄只到 4000 Hz 或 8000 Hz 時，新增加的高頻細軸點會照既有決策使用最近端帶平坦延伸，
  並標記為延伸資料，不冒充量測值。

## 拍板

音色評估範圍 20–8000 Hz 由老闆於 2026-09-18 在票 #345 第 2 格拍板，2026-09-22 在票 #347 再提醒
上限一定要到 8000 Hz。報表帶清單這次不加 8000 Hz、先另報密軸成本再問，是票 #347 第 4 項的既定順序，
由助理照票執行；傾斜擬合段不動，是因為它連著一條正式數字的推導、要動得老闆另拍，不是這次拍的。
