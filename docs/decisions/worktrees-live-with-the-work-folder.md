# 工作樹跟派工資料夾住一起，開與拆只走一支工具

## 問題

worktree（同一個 repo 的第二個工作目錄，一張票一棵）放哪裡、叫什麼、誰來拆。2026-09-19 量到的現況：
三棵樹丟在 `~/ghq/` 根層（那一層是別的專案的地方）；同一張票的派工資料夾、樹、分支三個名字對不起來
（`345-timbre`／`aosr-v3-345-timbre`／`feat/345-timbre-evaluator`）；票合了樹與分支沒人收，本機留著 77 條分支。
位置與名字沒有寫下來的規矩，靠每個對話自己記。

## 選項

1. 樹放 repo 裡面的隱藏目錄（例：`.worktrees/`）。
2. 樹放 repo 旁邊另開一個目錄。
3. 樹跟派工資料夾住一起：`~/aosr-v3-work/<票號>-<短名>/tree`。

## 決定

選項 3。一張票一個資料夾 `~/aosr-v3-work/<票號>-<短名>/`：工單與證據放那一層，樹住它底下的 `tree/`，
分支叫 `<種類>/<票號>-<短名>`，種類只認 feat、fix、docs、card、chore。資料夾、樹、分支三樣東西一個名字。

開樹、列樹、拆樹只走 `governance/worktrees.py`（`new`／`list`／`remove`），不再手打 `git worktree add`。
拆樹四個條件都要成立才拆：這條分支的 PR（合併請求）已經合進主線（合進別條分支的不算）、本機分支的頭等於 PR 的頭、
樹裡沒有改過或沒進版控的檔、被 `.gitignore` 蓋住的檔只有重建得回來的那幾種（環境、快取、本機那份測試收據）。
`list` 說「該拆」與 `remove` 真的去拆，問的是同一組條件：PR 合了但本機還有沒送出去的提交的樹，`list` 寫的是「別硬拆」。
拆的是 `tree/` 與本機分支；派工資料夾裡的工單與證據留著。不符合條件的樹這支工具不碰，要人看過再處理。

## 為什麼

v2 的事故 `accumulating-disk-state-has-no-owner`：工作樹累積到 111 棵 67 GB、5 棵髒樹沒有人認，
因為沒有一個地方說得出「這一棵是哪張票的、可以拆了沒」。住在票的資料夾裡，這兩題看路徑就有答案。

不放 repo 裡面：掃描工具、測試收集、搜尋都會掃進那個目錄，同一批檔算兩次；v2 還有一筆是在某一棵樹裡
跑起來的直譯器 import 到另一個 checkout 的程式碼。不留在 `~/ghq/` 根層：那一層的規矩是「網站／擁有者／repo」。

主線用 squash（把整條分支壓成一顆提交）合併，`git branch --merged` 看不出一條分支合了沒，所以拆樹去問 GitHub，
而且要比頭：合了之後本機又多提交的分支，拆掉就是丟工作。沒進版控的檔交給 git 自己擋，工具不加強制旗標；
但 git 的「乾淨」不看被忽略的檔、拆樹時會無聲一起刪掉（2026-09-19 找碴時實測），所以那一格工具自己先量，
量到清單以外的被忽略檔就不拆、把檔名印出來。

施工的工人沙箱只准寫自己的工作目錄，開不了樹；會開樹的只有主對話，所以一支工具加入口檔一行就管得到全部的開樹動作。

## 代價

這不是規矩卡：雲端看不到本機的樹，合併門口守不到。守得到的只有 `list` 把放錯地方、名字對不上、該拆沒拆的
標出來並回非零——要有人去跑它。手打 `git worktree add` 到別的地方，要等下一次 `list` 才看得見。
`list` 與 `remove` 要問 GitHub，沒有網路就做不了，會明說做不下去並回「這一跑不算數」的離開碼，不當成沒事。
「重建得回來的那幾種」是寫在工具裡的一張短清單：樹根層的環境與工具快取目錄、任何一層的位元組碼快取目錄、
本機那份測試收據的目錄；清單以外的被忽略檔一律擋。有人硬把要留的東西放進那幾個目錄裡，工具擋不到。
stash（暫存起來的改動）存在共用的地方，拆樹不會弄丟它，但它會跟那張票脫鉤，工具不管這件事。
派工資料夾本身（拆樹之後留下的工單與證據）什麼時候清，這張紙沒有管。
