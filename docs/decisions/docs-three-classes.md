# docs/ 只准三類，平行不分層，三道柵欄

## 問題

repo 清空後沒有 `docs/`。決策紙、設計文件、專案知識放哪、分幾類、每類最多幾份。

## 選項

1. 三類，分層放（例如 `docs/contract/decisions/`），為將來的格式約定預留位置。
2. 三類，平行不分層：`docs/decisions/`、`docs/design/`、`docs/cairn/`。
3. 只開 `docs/decisions/` 一類，其餘等真的有了再開。

## 決定

選項 2，加三道柵欄：

1. **限種類**（主柵欄）：工人紀錄、審查、進度快照、每票報告，一律不進 repo，只活在 issue 與 PR。`docs/` 只准三類——`decisions/` 放拍板過的東西（一題一檔，格式照「決定一題一張紙」）、`design/` 放設計文件、`cairn/` 放做過的事沉澱成的可重用知識（試過什麼沒用、外部硬限制、量錯的坑）。放錯種類 CI 紅。
2. **限數量**（第二道）：三類各設數量上限，用 `git ls-files` 數（以版控索引為準，不用檔案系統掃描，避免被忽略的檔算進去假紅），超過就紅，逼人先刪再加。上限數字寫在規矩卡裡，由那張卡的 PR 定。
3. **算得出來的不存檔**：現況、架構圖、耦合表只存指令不存結果，要看就現算。

## 為什麼

v2 事故 `docs-volume-buries-the-design`：`docs/` 長到 1046 份，其中 636 份是過程紀錄（383 工人紀錄、253 審查、75 進度快照），有用的是 76 份設計文件與 6 份知識。253 份審查沒人回頭讀，同一個問題重修兩次；6 月的架構分析 8 月三個工人都找不到，花一下午提議重做。9 月變 1437 份，715 份封存。**只設數量上限不夠，暴漲的那些從來沒被讀過，要限種類。**

選平行不分層：今天只有三類三個目錄，路徑短，數量上限直接對著三個目錄數；不為推想中的東西先開層。

## 代價

將來若出現「格式約定」這種不是一題一張的東西，要嘛塞進 `decisions/`，要嘛開第四類、改這張紙。
