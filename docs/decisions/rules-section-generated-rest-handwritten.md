# 規矩節生成，其餘手寫，上限 200 行

## 問題

規矩存在哪裡、以什麼形式存在，CLAUDE.md 是原稿還是產物。

## 選項

1. 照 v2，規矩手寫在 CLAUDE.md，守衛另寫在 pre-commit。
2. 整份 CLAUDE.md 由生成器產出。
3. 規矩節生成，座標、驗證指令、入口、習慣手寫。

## 決定

選項 3。一條規矩一個檔，放 `governance/rules/`，用 TOML，必填：人話一句、檢查指令、必紅樣本路徑、掃描範圍、離開碼三值（0 乾淨、1 違規、2 工具自壞）、執行它的 CI job 名、豁免帶到期日。湊不出必紅樣本的不是規矩，落到知識區。
CLAUDE.md 與 AGENTS.md 的規矩節由卡片生成、用標記包住、CI 重生比對，手改即紅。標記外手寫：座標、一行驗證指令、狀態與決策入口、七條習慣。全檔硬上限 200 行，寫成登記簿常數；改上限要一張決策紙，不得為了讓某次提交過而改。歷史不進 CLAUDE.md，往決策紙與知識區沉。

## 為什麼

v2 的 CLAUDE.md 432 行、九月改 31 次；規則、守衛範圍、實際程式三邊各自漂。核心九條的「禁裸 Any」與「禁 print」程式裡有 360 與 88 處違反，無機器抓，卻每次載入。治理數字曾憑心證當場改。

## 代價

要先寫生成器與比對檢查才能有第一份 CLAUDE.md。現有手寫的 CLAUDE.md 會被取代，其「scaffold 之後必做」兩項不執行。
